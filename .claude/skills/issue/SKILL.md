# issue

할 일을 GitHub 이슈로 만든다. **초안을 먼저 보여 주고, 사람이 승인해야만** 올린다.

## 입력

할 일 설명. 예) `/issue 관리자 로그인 API 만들기, JWT로`
설명이 한 줄도 없으면 무엇을 할지 한 번 묻는다.

## 만드는 순서

1. `.github/ISSUE_TEMPLATE/task.md`의 칸과 순서를 그대로 따라 초안을 만든다
2. 제목: `타입: 내용` — 커밋과 같은 모양 (한국어 한 줄, 50자 이내, 범위 표시 없음, 타입은 `git-convention` 스킬 표)
3. 본문 칸 채우는 법

| 칸 | 채우는 법 |
|---|---|
| 작업 설명 | 무엇을 왜 하는지 1~2줄 |
| 요구 사항 | 해야 할 일을 체크박스로 2~5개 |
| 참고 사항 | 관련 문서(`docs/...`)·이슈 번호. 모르면 비워 둔다 |
| 완료 조건 | 끝났다고 판단할 기준을 체크박스로 (예: "테스트 통과", "API 문서 반영") |

설명에 없는 내용은 지어내지 않는다. 모르는 칸은 비워 두고 초안 아래에 "채울 칸: ○○"으로 알린다.

4. 초안과 함께 이 작업에 맞는 **브랜치 이름**도 `git-convention` 규칙으로 제안한다

## 올리기 (사람이 "올려줘"라고 승인한 뒤에만)

```
gh issue create --title "<제목>" --body-file - <<'BODY'
<본문>
BODY
```

- 승인 없이 올리지 않는다. 초안을 고쳐 달라고 하면 고친 초안을 다시 보여 주고 다시 승인을 받는다
- `gh`가 없거나 로그인이 안 돼 있으면 올리지 말고 `gh auth login`이 필요하다고 알린다
- 올린 뒤 **이슈 번호와 URL**을 보여 준다. 이 번호는 나중에 `pr-body`가 `closes #번호`로 PR에 연결한다
- 브랜치를 만들어 달라고 하면 `git switch -c <브랜치>`를 실행한다 (`dev` 최신 기준: 먼저 `git fetch origin` 후 `git switch -c <브랜치> origin/dev`)
