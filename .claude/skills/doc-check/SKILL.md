# doc-check

`docs/` 안의 기획 문서끼리 서로 맞는지 본다. **코드는 보지 않는다.** 문서도 고치지 않는다.

## 읽는 것

`docs/rules/` 안의 문서. 사람이 문서를 지정하면 그것만 읽는다.

| 문서 | 비교에 쓰는 것 |
|---|---|
| `00-개요.md` | MVP 범위 (하는 것·안 하는 것) |
| `01-이야기로-보는-흐름.md`, `02-사용자-시나리오.md` | 예시의 행동 |
| `03-상태와-규칙.md` | 상태 전이 표, 역할별 권한 표, 보이는 범위, 불변식 |
| `05-ERD-초안.md` | 테이블·칸·제약, 행동 종류 |
| `06-요구사항-명세.md` | 기능 표, 추적표, 수용 기준, API 목록, 오류 코드, 설정값, 화면 명세, 화면 문구 |
| `08-화면-기본-틀.md` | 화면 그림, 문자 문구 |
| `GLOSSARY.md` | 용어 |

문서가 하나뿐이거나 없으면 "비교할 문서가 부족합니다"라고 알리고 멈춘다.

**어느 쪽이 맞는지**는 `docs/rules/06-요구사항-명세.md` 0장 "주제별로 더 깊게"의 "문서끼리 다르면"으로 정한다. 기능·수용 기준·API가 06과 다르면 06에 맞춰 고칠 곳이다. 06이 다루지 않는 자세한 내용은 그 표의 "더 깊게" 칸 문서가 맞고, 다른 문서의 같은 문장은 지우고 가리키기로 바꿀 곳이다. 결과의 설명에 "기준: ○○"를 붙인다. **단, 원칙(`decisions.md` "늘 지키는 원칙", 03 0장)·03 5장 불변식·03 3장 권한 표와 06이 다르면** 어느 쪽도 맞다고 정하지 않고 "기준: 사람이 정할 것(/decide)"으로 적는다.

## 찾는 것

1. 시나리오에 있는 행동인데 API가 없음
2. API가 저장·조회하는 값인데 ERD에 칸이 없음
3. ERD에 있는데 어느 시나리오에서도 쓰지 않는 테이블·칸
4. 같은 것을 문서마다 다른 이름으로 부름 (예: 수리 건 / 하자 건)
5. 상태 이름이나 상태 전이가 문서끼리 다름
6. 한 테이블을 두 역할(임대인·세입자 등)이 고친다고 적힌 곳
7. 같은 정의·목록·숫자를 "적는 곳"이 아닌 문서가 다시 적은 곳 (가리키기만 해야 함)
8. 06 기능 표·추적표가 가리키지 않는 03·05·08의 규칙·테이블·행동 (06 지도에서 빠진 곳)
9. 머리말이나 본문에 "다르면 ○○가 맞다"처럼 06 0장 "문서끼리 다르면"과 다른 말을 적은 곳

## 하지 않는 것

- 문장 다듬기, 설계 의견
- 문서 직접 고치기

## 결과 모양

| 번호 | 문서A 위치 ↔ 문서B 위치 | 설명 |
|---|---|---|
| 1 | `02-사용자-시나리오.md` 시나리오 3 ↔ `06-요구사항-명세.md` 4-6 | "수리 완료 확인" API 없음. 기준: 06 |

- 번호는 위 "찾는 것"의 번호
- 위치는 `파일` + 제목이나 줄 번호
- 없으면 `어긋남 없음` 한 줄
