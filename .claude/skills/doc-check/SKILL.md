# doc-check

`docs/` 안의 기획 문서끼리 서로 맞는지 본다. **코드는 보지 않는다.** 문서도 고치지 않는다.

## 읽는 것

`docs/rules/` 안의 문서. 사람이 문서를 지정하면 그것만 읽는다.

| 문서 | 비교에 쓰는 것 |
|---|---|
| `00-개요.md` | MVP 범위 (하는 것·안 하는 것) |
| `02-사용자-시나리오.md` | 시나리오의 행동 |
| `03-상태와-규칙.md` | 상태 전이 표, 역할별 권한 표 |
| `05-ERD-초안.md` | 테이블·칸·제약 |
| `06-요구사항-명세.md` | 기능 표, 수용 기준, API 목록, 오류 코드 |
| `08-화면-기본-틀.md` | 화면과 버튼 문구 |
| `GLOSSARY.md` | 용어 |

문서가 하나뿐이거나 없으면 "비교할 문서가 부족합니다"라고 알리고 멈춘다.

**어느 쪽이 맞는지**는 `docs/README.md` "문서끼리 다르면"으로 정한다. **기준점은 06**이고, 서로 다르면 06 → 03 → GLOSSARY → 05 → 08 순서로 앞의 것이 맞다 (컨벤션은 루트 `AGENTS.md`). **단, `decisions.md` "늘 지키는 원칙"·03 5장 불변식·03 권한 표와 06이 다르면 어느 쪽도 맞다고 정하지 않고** "기준: 사람이 `/decide`로 정할 것"으로 적는다. 결과의 설명에 "기준: ○○"를 붙인다.

## 찾는 것

1. 시나리오에 있는 행동인데 API가 없음
2. API가 저장·조회하는 값인데 ERD에 칸이 없음
3. ERD에 있는데 어느 시나리오에서도 쓰지 않는 테이블·칸
4. 같은 것을 문서마다 다른 이름으로 부름 (예: 수리 건 / 하자 건)
5. 상태 이름이나 상태 전이가 문서끼리 다름
6. 한 테이블을 두 역할(임대인·세입자 등)이 고친다고 적힌 곳

## 하지 않는 것

- 문장 다듬기, 설계 의견
- 문서 직접 고치기

## 결과 모양

| 번호 | 문서A 위치 ↔ 문서B 위치 | 설명 |
|---|---|---|
| 1 | `02-사용자-시나리오.md` 시나리오 3 ↔ `06-요구사항-명세.md` 4-6 | "수리 완료 확인" API 없음. 기준: 06 |

- 번호는 위 "찾는 것"의 번호
- 위치는 `파일` + 제목이나 줄 번호
- 없으면 `어긋남 없음` 한 줄
