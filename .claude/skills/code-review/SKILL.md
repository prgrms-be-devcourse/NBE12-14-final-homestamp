# code-review

PR 전에 **바뀐 코드만** 보고 규칙 위반을 찾는다. 파일은 고치지 않는다.

## 보는 범위

1. `git diff origin/dev...HEAD` — 이 브랜치에서 커밋한 변경
2. `git diff HEAD` — 아직 커밋하지 않은 변경 (있으면 같이 본다)

바뀐 줄을 이해하는 데 필요하면 주변 코드를 읽어도 되지만, **지적은 바뀐 줄에만** 한다.

## 볼 것

- **팀 규칙** (`AGENTS.md`)
  - 이미 `dev`에 들어간 Flyway 마이그레이션(`V*.sql`)을 고쳤는지 → 새 V 파일로 해야 한다
  - 비밀값(키, 비밀번호, 토큰)이 코드·설정 파일에 들어갔는지
- **트랜잭션**: 쓰기 작업에 트랜잭션이 없거나, 트랜잭션 안에서 외부 호출(HTTP, 메일)을 하는지

### 프로젝트 원칙 점검

기준은 원본 문서다. 아래는 **코드에서 확인할 수 있는 것만** 뽑은 점검 목록이고, 판단이 애매하면 원본을 읽는다.
원본: `docs/decisions.md` "늘 지키는 원칙" · `docs/rules/09-프로젝트-구조.md` 3장 "부르는 방향" · `docs/rules/03-상태와-규칙.md` 3장 "역할별 권한 표". 이 문서들과 `docs/rules/06-요구사항-명세.md`(수용 기준·API·오류 코드)가 다르면 06이 맞다 (`docs/README.md` "문서끼리 다르면")

| 원칙 | 코드에서 볼 것 |
|---|---|
| 덧붙이기만 (원칙 1, `05-ERD-초안.md` 0장 "테이블 세 종류") | 위반: **A(행동 기록)·B(사실 행)를 고치거나 지움**, **C(상태 행)에서 상태·기한·version·"지금 판" 말고 다른 칸을 바꿈**, **`apply`(`*Transitions`, 09 4장) 밖에서 C의 상태를 바꿈**. 정상: `apply`가 C의 그 칸들을 바꾸는 것, B를 고칠 때 이전 판을 가리키는 새 행을 만드는 것. 예외(고치고 지울 수 있음): 같은 문서 "원칙의 예외"의 신원·연락처 칸, 개인정보가 찍힌 사진 파일 |
| 서버 시각만 (원칙 5) | 요청으로 받은 시각을 기록 시각으로 저장 |
| 개인정보 (원칙 7) | 주민등록번호 칸, 외부 CDN·OCR·분석 SDK 의존성 추가, 가리지 않은 휴대폰 번호를 응답에 담음 |
| 막히는 쪽으로 (원칙 8) | 가리기·보호 처리가 실패했을 때 `catch`에서 원본을 그대로 저장·응답하고 넘어감 |
| 도메인을 넘는 참조 (09) | 다른 도메인 엔티티에 JPA 관계(`@ManyToOne` 등) — **ID 값만** 가져야 한다 |
| 부르는 방향 (09) | 아래층(`action`·`correction`·`notification`)·`global`이 도메인을 import, `respond`가 아닌 곳에서 `respond`를 부름, 09 "같은 도메인 층끼리 방향" 표에 없는 방향으로 부름 |
| 잠금 (09) | 행동을 처리하면서 호실 기록 행을 맨 먼저 잠그지 않음 |
| 권한 (03) | 권한 표의 △ 조건("상대 측만", "등록 측", "초대받은 사람") 확인이 빠짐, 링크 열람자가 ✕ 행동을 할 수 있음 |

판정하지 않는다(원칙 3)처럼 문구·설계에 관한 원칙은 이 리뷰에서 보지 않는다 (사람이 PR에서 본다).

## 안 볼 것

- 들여쓰기, 줄바꿈, import 순서 (포매터가 맞춘다)
- 이름 취향, "이렇게 쓰면 더 예쁘다" 같은 의견

## 결과 모양

```
back/src/main/java/.../LeaseService.java:42 — 세입자 ID를 확인하지 않아 다른 사람 계약을 조회할 수 있음
back/src/main/resources/db/migration/V1__init.sql:10 — dev에 들어간 마이그레이션 수정, 새 V 파일로 옮길 것
```

- 한 줄에 하나, `파일:줄 — 한 줄 이유`
- 심각한 것부터
- 없으면 `위반 없음` 한 줄
