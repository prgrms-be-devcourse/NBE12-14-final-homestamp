# AI 실수 기록

AI(Claude·Codex)가 **반복한 실수**나 **위험했던 실수**를 남긴다. AI는 작업을 시작하기 전에 이 파일을 읽는다.

## 규칙
- 같은 실수를 두 번 했거나, 한 번이라도 되돌리기 어려운 일이 될 뻔했으면 기록한다
- AI는 기록을 **제안만** 한다. 사람이 승인한 뒤에만 추가한다
- 새 기록은 맨 위에 쓴다. 한 기록은 10줄 이내로 쓴다
- 훅이나 스킬로 막을 수 있게 되면 "막는 장치"에 적는다. 기록은 지우지 않는다
- 더는 일어나지 않는 기록은 지우지 말고 제목 끝에 `(해결됨: YYYY-MM-DD)`를 붙인다

## 쓰는 모양

```
### YYYY-MM-DD 한 줄 제목
- 무슨 일: AI가 무엇을 했나
- 왜 문제: 그대로 두면 무슨 일이 생기나
- 앞으로: AI가 다음부터 어떻게 하나
- 막는 장치: 없음 / 훅·스킬 이름
```

## 기록

### 2026-11-13 한글 파일 이름을 git diff로 거르다가 검사가 조용히 통과함
- 무슨 일: CI의 결정 기록 검사에서 `git diff --name-only` 결과를 `^docs/rules/`로 걸렀는데, git이 한글 경로를 `"docs/rules/04-\354…"`처럼 따옴표로 내보내 한 건도 걸리지 않았다
- 왜 문제: 규칙 문서가 모두 한글 이름이라 검사가 아무것도 막지 못한 채 늘 통과한다. CI가 초록이라 눈치채기 어렵다
- 앞으로: 한글 경로를 다루는 git 명령은 `git -c core.quotepath=off`를 쓰고, 검사가 "통과"했을 때도 로그 메시지가 예상과 같은지 한 번 본다
- 막는 장치: 없음 (시험 PR로 확인)

### 2026-11-12 sed에 셸 변수를 넣다가 문서에 변수 이름이 그대로 들어감
- 무슨 일: `AGENTS.md`에 규칙 한 줄을 넣으면서 sed 안에 `$RULE`을 썼는데, 값 대신 `$RULE` 글자가 그대로 들어갔다
- 왜 문제: 규칙 문서가 조용히 깨진다. diff를 보지 않으면 모르고 지나간다
- 앞으로: 여러 줄·특수문자가 있는 문서 수정은 sed 대신 Edit 도구를 쓰고, 고친 뒤 해당 줄을 다시 확인한다
- 막는 장치: 없음
