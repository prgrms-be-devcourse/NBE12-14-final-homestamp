### 꼭 알아야 할 약속 열 가지

| # | 약속 | 내용 |
|---|---|---|
| 1 | 형태 | **반응형 웹.** 문자 링크를 누르면 설치 없이 열린다 |
| 2 | 가입 | 응답하려면 회원가입(임차인·임대인은 고르지 않고, 연결할 때 정해짐). 가입 때 휴대폰 문자 인증 한 번. 한 번호는 한 계정에만 |
| 3 | 호실 | 임대인·임차인 모두 호실 기록을 만들고 상대를 초대한다. 상대 번호는 **초대할 때** 넣는다(호실 만들 때는 선택). 초대하기 전에는 문자가 나가지 않는다 |
| 4 | 연결 | 초대받은 사람의 인증 번호 = 초대받은 번호이면, **연결 확인 화면**에서 한 번 눌러 연결 |
| 5 | 링크 | 공유한 기록 **자체를 보는 창**. 가입 전에는 읽기만(사진·설명·처리 상태·시간·고친 이력, 주소는 시·구·동까지) |
| 6 | 문자 | 상대가 **응답해야 하는 일만** 문자 + 서비스 안 알림. 나머지는 서비스 안 알림만. 거의 동시에 가는 문자는 한 통으로 모은다 |
| 7 | 기다림 | 48시간 응답 없으면 재통지, 그 뒤 24시간에도 없으면 **"○○ 님 확인 없음"**. 요청에 따라 상대가 혼자 진행할 수 있게 되거나(하자 확인, 종료, 점검, 정산 끝내기) 표시만 남는다(돈 확인 등). 늦게 답해도 정산 완료 전까지 반영된다 |
| 8 | 혼자 진행 | **사실은 혼자 남길 수 있고, 합의는 혼자 만들 수 없다.** 확인과 합의는 연결한 사람끼리만: 연결 전 상대에게 돈은 혼자 기록이 된다 |
| 9 | 수리와 돈 | **따로 끝난다.** 하자 인정(맞아요 / 보충 요청됨 / 이견), 수리 진행(시작 전 → 처리 중 → 처리 완료), 돈 상태(미정 / 합의 대기 / 합의됨 / 이견 / 비용 없음) |
| 10 | 기록 | 지우거나 덮어쓰지 않고 고친 이력이 쌓임. 같이 확인하기 전엔 그냥 고쳐지고, 같이 확인한 뒤엔 무엇이든 확인한 내용이 앞에 남고 고친 것은 아래에 붙어 상대가 확인해야 바뀐다. 돈은 [바꾸기](새 제안) |

### 수리와 돈의 조합

| | 돈: 미정 | 돈: 합의 대기·합의됨 | 돈: 이견 |
|---|---|---|---|
| 수리 안 끝남 | 막 등록했거나 진행 중 | 견적 보고 미리 합의 | 고치기 전부터 돈 다툼 |
| 수리 끝남 | **고쳤지만 돈 얘기 아직** | 합의됨이면 **완전히 끝남** | **고쳤지만 돈 다툼** |

홈 화면에는 **"고쳤지만 돈이 남은 건"**을 따로 모아 보여 준다. 퇴거 때 돈이 안 끝난 건은 정산의 "확인 대기"·"이견" 칸으로 모인다.

## 시나리오 1. 거주 중 하자 → 집주인 첫 연결 → 수리 → 종료

> **보여 주는 것**: 연락이 중간에서 끊기는 문제를 서비스가 어떻게 바꾸는지. 포인트 기능이에요.

|---|---|---|---|---|---|
| 1 | 세입자 | 가입(문자 인증) → 호실 기록 만들기(이 호실에서 **임차인**, 시·구·동, 호실 별칭. 집주인 번호는 선택이라 지금 넣음) | - | 회원, 호실 기록, 당사자(세입자: 계정 / 집주인: 번호만) | (인증 문자) |

| 8 | 집주인 | 업체를 불러 "수리 시작" | 처리 중 | 행동 "수리 시작" | - |

### 갈림길

| 갈림길 | 어디서 | 무슨 일이 | 남는 기록 |
|---|---|---|---|
| 1-A. 집주인이 응답하지 않음 | 3번 뒤 | 48시간 뒤 재통지, 24시간 더 → "정호 님 확인 없음 · 아직 연결하지 않았어요". 세입자는 혼자 진행(수리 시작, 이미 확인 없음이라 종료 요청 없이 바로 "처리 완료(세입자 확인)")할 수 있다. 지불은 **혼자 기록**이 되고(연결 전이라 확인 요청이 가지 않음), 집주인이 연결하면 확인 카드에 모인다. 돈은 합의됨이 되지 않는다 | 통지 2건, 확인 없음 표시 |
| 1-B. 하자 자체를 부정 | 7번 | [아니에요 · 더 필요해요] → "사실과 달라요"(이견, 사유 필수: "방문해 보니 물 자국이 없어요") 또는 "더 필요한 게 있어요"(보류). 표시가 붙지만 **누구든 수리를 시작할 수 있다.** 세입자는 사진·설명을 하나 이상 더해 [보충하고 다시 확인 요청]을 할 수 있다(한 기록에 7일에 한 번) | 행동 "이견"·"보류", "보충", "수리 시작" |
| 1-C. 하자는 맞지만 책임이 다름 | 7번 | **확인 + 부담 제안**("세입자 부담", 사유 "사용 부주의로 보임"). 수리는 진행된다. 원인에 대한 생각은 각자 **원인 설명**으로 남긴다(집주인 "근거: 업체 소견, 소견서 사진", 세입자 "근거: 직접 봤어요"). 서비스는 어느 쪽이 맞는지 정하지 않는다. 원인 설명(Should)이 아직 없으면 같은 생각을 진행 상황에 글과 사진으로 남긴다(부담은 원래 원인 설명과 상관없이 제안·합의로 정한다) | 행동 "확인", "부담 제안", 원인 설명 |
| 1-D. 부담 제안에 동의 못 함 | 10번 | [아니에요 · 다른 안] → 사유 + 다른 안(선택, 예: 나눠서 32,500원씩). 다른 안이 새 제안이 된다. 합의 뒤에 바꾸려면 [바꾸기](상대가 동의할 때까지 지금 합의 그대로). 횟수 제한 없이 회차 표시, 3회째부터 안내 한 줄 | 행동 "이견", "다른 안" |
| 1-E. 아직 안 고쳐짐 | 12번 | "아직 안 됐어요" + 사유 → 처리 중 | 행동 "아직 안 됐어요" |
| 1-F. 설명을 잘못 씀 | 아무 때 | [고치기]. 집주인이 확인하기 전이면 그냥 고쳐지고, 확인한 뒤면 확인한 설명이 앞에 그대로 보이고 "내가 고친 내용"이 아래에 붙어 집주인에게 확인 요청이 간다(집주인이 확인하면 앞으로). 부위·지불 금액도 같다. 사진은 고치지 않고 더하거나 "잘못 올린 사진"으로 표시한다. 링크에서도 고친 이력이 보인다 | 행동 "고치기"(원래 기록 참조) |
| 1-G. 번호를 잘못 입력 | 3번 | 모르는 사람은 링크 화면(위치·개인정보 없음)만 본다. 세입자 화면에 "링크 열람 1회" → 번호 고쳐 다시 초대 → 이전 링크 자동 무효 | 번호 변경, 새 초대 |
| 1-H. 고쳤는데 돈 얘기는 아직 | 12번 | 종료는 된다. 돈은 미정으로 남아 "고쳤지만 돈이 남은 건"에 나타난다 | - |
| 1-I. 돈이 들지 않음 | 11번 전 | 누구든 "비용 없음" 제안 → 상대 확인 | 행동 "비용 없음" |
| 1-J. 집주인이 하자를 등록 | 2번 대신 | 정기 점검 등에서 집주인이 등록 → 세입자에게 문자 → 세입자가 확인 또는 이견. 부담 제안이 함께 오면 1-C·1-D로 | 행동 "등록"(집주인) |
| 1-K. 종료 요청에 답이 없음 | 11번 뒤 | 미확인 뒤 요청한 측 확인으로 종료: "처리 완료(집주인 확인)" + "서윤 님 확인 없음". 세입자는 나중에 사유를 달아 다시 열 수 있다 | 행동 "종료(요청 측 확인)" |
| 1-L. 같은 곳이 다시 샘 | 완전히 끝난 뒤 | 양측 확인으로 끝난 건은 다시 열지 않는다. 새 수리 건을 만들고 "이전 수리 건 이후 재발"로 참조 | 새 수리 건 |
| 1-M. 급해서 먼저 고침 | 2번 뒤 | 세입자가 집주인 확인 전에 "수리 시작"("상대 확인 전 수리 시작" 표시). 집주인은 나중에 들어와도 정산 완료 전까지 **하자 인정**(맞아요 / 보충 요청 / 이견)을 남길 수 있다. 종료 확인 때 비어 있으면 함께 묻는다 | 행동 "수리 시작", "하자 인정" |
| 1-N. 수리가 멈춤 | 8번 뒤 | 수리 시작 뒤 14일 넘게 새 행동이 없어 홈의 "오래 멈춘 건"에 뜬다("처리 중 · 15일째"). 세입자가 **진행 상황 남기기**("부동산이 윗집 합의 때문에 6개월 기다리라고 해요") + **진행 상황 묻기** → 집주인에게 문자. 집주인이 "윗집과 직접 이야기해 볼게요"로 답하면 요청이 닫힌다. 답이 없으면 "물었는데 답이 없었다"가 미확인으로 남는다 | 행동 "진행 상황", "진행 상황 묻기" |

## 시나리오 2. 집주인이 먼저 시작: 호실 등록 → 세입자 초대 → 입주 점검

| # | 누가 | 화면에서 하는 일 | 남는 기록 | 문자 |
|---|---|---|---|---|
| 1 | 집주인 | 가입 → 호실 기록 만들기(이 호실에서 **임대인**, 세입자 번호) | 회원, 호실 기록, 당사자(세입자: 번호만) | - |
| 2 | 집주인 | 입주 전 부위별 기존 하자와 사진(기준 기록) → 세입자 초대 | 점검(입주), 점검 항목, 사진, 초대 | **세입자에게** 초대 링크 |
| 3 | 세입자 | 링크 열람 → 가입 → 번호 일치 → 연결 확인(세입자로 연결) → 연결 | 당사자에 계정 연결 | (인증 문자) |
| 4 | 세입자 | 항목마다 [맞아요] 또는 [아니에요 · 더 필요해요](보류·이견, 사유), 문제없는 항목은 "남은 항목 모두 확인". 빠뜨린 하자는 [+ 빠뜨린 하자 더하기](새 기록이라 집주인 확인) | 행동 "확인", "이견", "항목 더하기" | **집주인에게** 확인 요청 |
| 5 | 서버 | 모든 항목에 그 항목을 쓰지 않은 쪽의 답(확인·보류·이견) 또는 확인 없음이 붙으면 잠금(세입자가 더한 항목은 집주인이 답해야 함) | 잠금 시각 | - |

- 점검 항목은 **적은 하자만**이다. 28개 부위를 다 누를 필요는 없고, 적지 않은 부위는 "이상 없음"이 아니라 "기록 없음"으로 보인다.
- 집주인이 입주 점검을 쓰지 않았다면 세입자가 **먼저 시작해서 기준 기록을 쓸 수 있다**(먼저 시작한 측이 기준). 작성 중에는 상대에게 "작성 중"만 보이고, 상대도 빠뜨린 하자를 더할 수 있다(기준 측이 확인). 작성 중이 7일을 넘으면 상대가 지금까지 쓴 것으로 확인 요청을 보낼 수 있다. 잠긴 뒤 빠뜨린 하자는 "잠긴 뒤 추가(날짜)"로 더하고, 살면서 생기거나 나빠진 하자는 수리 건으로 남긴다.
- 세입자가 이미 같은 동에 자기 호실 기록을 만들어 두었다면, 3번의 연결 확인 화면에서 먼저 **"이 기록과 같은 집인가요?"**를 묻는다. 같은 집이면 **"상대 기록에 합류 / 거절하고 내 기록으로 초대"**를 고른다. 기록이 많은 쪽이 추천으로 표시된다. 합류하면 내 옛 기록은 "합류 전 기록"으로 나만 읽을 수 있고, 거기 있던 사진·날짜를 함께 보는 기록으로 옮기는 것은 확장이다(그 전에는 내려받기 ZIP으로 남긴다).
- 세입자 시작과 집주인 시작은 **같은 호실 기록 구조**로 끝난다. 입주 점검 기준 기록을 먼저 쓰는 쪽만 다르다.

## 시나리오 3. 세입자 혼자 기록 (집주인 없이)

| # | 누가 | 화면에서 하는 일 | 남는 기록 |
|---|---|---|---|
| 1 | 세입자 | 가입 → 호실 기록 만들기(**집주인 번호 없이**). 하자를 올릴 때마다 "집주인에게 알릴까요?"에 "나중에"(또는 공유 동의 화면에서 [나만 보기]) | 호실 기록, 당사자(집주인: 비어 있음) |
| 2 | 세입자 | 입주 점검, 하자 등록, 사진을 혼자 기록. 직접 고친 하자는 종료 요청 없이 "처리 완료(세입자 확인)" | 점검, 수리 건, 사진 |
| 3 | 세입자 | 나중에 하자 화면의 "알리기" 또는 호실 화면의 "집주인 초대하기" → **이때 집주인 번호를 넣고** 그동안의 기록과 함께 시나리오 1로 이어진다 | 상대 번호, 초대, 통지 |

혼자 기록하는 동안 호실 맨 위에 **"혼자 기록하고 있어요 · [집주인 초대하기]"**가 한 번 보인다(줄마다 붙이지 않음). 상대가 연결되면 그동안의 기록(입주 점검, 끝낸 수리 건, 지불)마다 확인 요청이 생겨 **확인 카드**에 모이고, 첫 문자 없이(연결한 순간 화면을 보고 있으므로) 48시간 뒤 남은 것이 있으면 문자 한 통이 간다. 여러 기록을 한꺼번에 맞다고 하는 버튼은 없다. 집주인이 혼자 만든 호실도 같다("처리 완료(집주인 확인)"). 연결 전에 끝낸 정산은 "혼자 정리한 정산"으로 남는다.

## 시나리오 4. 입주 점검 → 퇴거 → 정산 → 보증금 수령

| # | 누가 | 화면에서 하는 일 | 남는 기록 | 문자 |
|---|---|---|---|---|
| 1 | 세입자 | 입주 날 부위별 기존 하자와 사진 → 집주인에게 확인 요청 | 점검(입주), 점검 항목, 사진 | **집주인에게** 확인 요청 |
| 2 | 집주인 | 항목마다 확인 → 잠금 | 행동 "확인", 잠금 시각 | - |
| 3 | (거주) | 시나리오 1 같은 수리 건이 쌓인다 | 수리 건들 | - |
| 4 | 세입자 | 퇴거 점검 시작: 같은 부위 목록으로 퇴거 사진 | 점검(퇴거), 사진 | - |
| 5 | 서버 | **정산이 열리고** 열린 수리 건을 먼저 보여 준다 | 정산 열림 | - |
| 6 | 둘 다 | 부위마다 입주 · 수리 · 퇴거 사진을 나란히. "입주 기존 하자 / 거주 중 하자" 표시 | (조회) | - |
| 7 | 세입자 | **보증금 금액 적기**(10,000,000원). 확인 전에도 정산은 막히지 않는다("보증금 확인 전") | 행동 "보증금 제안"(화면 말은 금액 적기) | **집주인에게** 확인 요청 |
| 8 | 둘 다 | **수리 건에서 온 후보**: 누수 +65,000(집주인 부담인데 세입자가 냄) → [넣기]. 이미 합의된 건이라 상대는 한 번 눌러 확인 | 정산 항목(출처: 수리 건) | 상대에게 확인 요청 |
| 9 | 집주인 | **직접 입력**: 관리비 미납 −70,000, 벽지 도배 −150,000(원상복구, 방 › 벽 연결) | 정산 항목(출처: 직접 입력) | **세입자에게** 확인 요청 |
| 10 | 세입자 | 관리비 [동의] → 합의됨. 도배는 [아니에요 · 다른 안]("입주 점검의 기존 하자") + 다른 안 0원 | 행동 "확인", "이견", "다른 안" | **집주인에게** 확인 요청 |
| 11 | 둘 다 | **합의된 항목으로 계산한 금액** = 10,000,000 − 70,000 + 65,000 = 9,995,000원. 정해지지 않은 −150,000원은 따로 보인다 | (조회) | - |
| 12 | 집주인 | 다투는 150,000원을 남기고 9,845,000원 반환 기록. 화면에는 "차이 150,000원"만 | 반환 기록 1 | **세입자에게** 수령 확인 |
| 13 | 세입자 | "받았어요" + 퇴거 점검 마침 → **거주 종료**(링크 닫힘, 새 수리 건 없음). 도배 이견은 정산에서 계속 열려 있다 | 행동 "수령 확인", "점검 마침" | - |
| 14 | 둘 다 | 도배를 75,000원으로 합의 → 반환 기록 2(75,000원) → 수령 확인 → "정산 끝내기" 요청(따로 문자, 기다리는 동안 정산이 바뀌면 다시 요청) → 확인 → **정산 완료** | 반환 기록 2, 행동 "정산 끝내기" | 상대에게 확인 요청 |

### 퇴거와 정산에서 기억할 것

- **직접 입력을 따로 받는 단계는 없다.** 정산 화면의 "항목 추가" 버튼 하나다.
- 후보를 **넣는 것도 빼는 것도 제안**이라 상대 확인이 필요하다. 한쪽이 상대 몫을 혼자 지울 수 없다.
- 수리 건의 합의나 같이 확인한 금액이 나중에 바뀌면 그 정산 항목은 다시 확인 대기로 돌아간다. 직접 넣은 항목의 금액·사유는 [바꾸기](새 제안)로 바꾼다.
- 받은 금액이 기록과 다르면 세입자는 [아니에요 · 더 필요해요](금액이 달라요, 사유)를 남기고 실제 받은 금액으로 [받았어요(혼자)]를 적는다. 두 기록은 같은 송금으로 묶여 한 번만 센다.
- 집주인이 반환을 기록하지 않아도 세입자는 혼자 "받았어요"를 남길 수 있다("정호 님 확인 없음" 표시).
- "반환 예정액·받아야 할 돈"처럼 권리로 읽히는 말은 쓰지 않는다.
- 세입자가 "점검 마침"을 눌러 거주 종료가 돼도 **퇴거 점검은 아직 잠기지 않는다.** 집주인은 그 뒤에도 항목마다 확인·이견을 남기고, 빠진 하자를 사진과 함께 더할 수 있다("거주 종료 뒤 추가" 표시).
- **집주인이 "이사함"이나 "점검 마침"을 누르면** 바로 끝나지 않고 세입자에게 거주 종료 확인을 요청한다(응답 없으면 미확인 뒤 적용). 집주인이 혼자 세입자의 기록 권한을 끊지 못하게.
- 상대가 거주 중에 한 번도 가입하지 않았다면 정산은 혼자 정리해 끝낼 수 있고("혼자 정리한 정산"), 바깥에서 이야기할 때는 인쇄·내려받기를 쓴다. 정산 초대 링크(Should)가 있으면 내용 없이 "정산 확인 요청이 있어요" + 가입하기로 함께 확인하자고 권한다.
- 정산이 끝나면 화면에 "정산 완료 · ○○에 삭제돼요"가 보이고, 그때까지 읽기와 내려받기만 된다.

### 늦은 입주 점검

- 거주 중에 처음 가입한 세입자도 입주 점검을 만들 수 있다.
- **"입주 후 등록(등록일)"** 표시와 함께 사진 옆에 "입주 후에 등록된 기록이에요. 입주 당시 상태와 다를 수 있어요"를 보여 준다.
- "효력이 없다" 같은 법적 판단 문구는 쓰지 않는다.

## 5. 보내는 사람이 보는 통지 상태

기록마다 **지금 가장 앞선 상태 한 줄**만 보이고, 지난 단계는 [알림 이력 ▸]에 시각과 함께 있다.

```
욕실 천장 물 자국 · 집주인에게 보낸 확인 요청
 받았어요 · 확인 기다림 41시간 남음          [알림 이력 ▸]
```

| 상태 | 한 줄 |
|---|---|
| 모으는 중 | 곧 보낼게요 |
| 밤·한도로 미뤄짐 | 내일 아침에 보낼게요 |
| 업체가 받음 | 보냈어요 · 받았는지 확인 중(남은 시간은 받은 뒤부터) |
| 휴대폰에 도착 | 받았어요 · 확인 기다림 ○시간 남음 |
| 링크를 엶 | 열어 봤어요 |
| 최종 실패 | 문자가 가지 않았어요 · [번호 고치기] [이 번호가 맞아요, 다시 보내기] |
| 문자를 끈 회원 | 서비스 안 알림으로 알렸어요(이때부터 기다림을 셈) |

"받았어요"는 상대 휴대폰에 도착했다는 통신사 결과까지이고, 읽었다는 보장은 아니다. 확인 없음은 전달된 통지 두 건이 있을 때만 붙는다(받지도 못한 사람을 확인 없음으로 몰지 않는다). 화면에 "발송 성공"이라는 말은 쓰지 않는다.
