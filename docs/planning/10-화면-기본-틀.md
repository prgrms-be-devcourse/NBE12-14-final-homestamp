# 화면 기본 틀

> **누가 읽나**: 와이어프레임을 그리는 사람, 화면을 만드는 프론트 담당, 화면에 맞춰 API를 만드는 백엔드 담당, 그리고 이 저장소를 읽는 AI.
> **무엇인가**: 지금까지 정하고 검증한 규칙(`3-상태와-규칙.md`)이 **화면에 어떻게 보여야 하는지**를 장면별로 고정한 기준이에요. 디자인(색, 배치, 크기)은 자유예요. 다만 **[반드시]**라고 적힌 것은 규칙 때문에 지켜야 해요. 더 좋은 화면이 있으면 이 문서와 비교해 이야기해요.
> **왜 필요한가**: 팀이 화면을 API 말("accept-all", "REQUESTED")로 이야기하다가 서로 다른 화면을 떠올렸어요. 이 문서는 "이렇게 보인다"를 먼저 정하고, 장면마다 **누르면 → 서버가 하는 일**을 한 줄씩 붙였어요.
>
> 등장인물: 세입자 **정서윤**(휴대폰에 익숙), 집주인 **김정호**(58세, 문자 링크로 들어옴, 새 앱을 꺼림).
> 그림의 `[ ]`는 버튼, `( )`는 작은 보조 버튼, `▸`는 눌러야 펼쳐지는 것이에요.

## 0. 화면 원칙

| # | 원칙 | 화면에서 지키는 법 |
|---|---|---|
| 1 | **쉽게 남기고 쉽게 답한다** | 기록 하나에 크게 보이는 버튼은 최대 두 개. 지난 이력은 접어 둔다. 기록이 귀찮으면 카톡을 뒤지는 것과 다르지 않다 |
| 2 | **한 줄에 한 뜻** | 같은 뜻은 하나의 말로, 다른 뜻은 다른 줄로. 수리 건은 하자 / 수리 / 돈 세 줄 |
| 3 | **판정하지 않는다** | 탓하거나 결론 내리는 말을 쓰지 않는다. "답하지 않았어요" 대신 "72시간 동안 답이 오지 않았어요", "책임 있음" 대신 "부담: 집주인 65,000" |
| 4 | **누구에게도 불리하게 보이지 않는다** | 사실을 빠짐없이 함께 보인다(예: "문자를 꺼 두어 서비스 안 알림으로만 알렸어요") |
| 5 | **문자로 도배하지 않는다** | 한 기록의 확인 요청은 문자 한 통. 다시 요청은 7일에 한 번. 덧붙이기는 문자 없음. 하루 한도(받는 번호당 5통). 21~08시는 아침에 |
| 6 | **버튼은 서버가 준 것만** [반드시] | 화면은 "지금 누를 수 있는 것"을 판단하지 않는다. 서버가 주는 `availableActions`에 있는 버튼만 그린다 |
| 7 | **내부 말을 쓰지 않는다** | 도장, 판, 안건, 표현 정정 같은 말은 화면에 쓰지 않는다(13장 표) |

## 1. 수리 건 카드: 세 줄

수리 건 하나에는 **서로 다른 세 가지 일**이 따로 움직여요. [반드시] 세 줄로 나눠 보여요.

```
┌ 욕실 › 세면대 · 수전에서 물이 새요 ─────────────────────────┐
│ 하자   정호 님 확인 ✓ · 11/15                                │
│ 수리   처리 중 · 6일째                                       │
│ 돈     합의 · 집주인 60,000 / 세입자 22,000                  │
│                                                              │
│ 사진 3장 · 진행 상황 2 · 원인 설명 1             [경과 ▸]   │
└──────────────────────────────────────────────────────────────┘
```

| 줄 | 묻는 것 | 보일 수 있는 값 |
|---|---|---|
| **하자** | 이런 하자가 있나? | 확인 기다림 · 남은 시간 / 정호 님 확인 ✓ / 보충 요청됨 / 이견 / 정호 님 확인 없음 · 이유 |
| **수리** | 고치고 있나? | 시작 전 · N일째 / 처리 중 · N일째 / 종료 확인 기다림 / 처리 완료(둘 다 확인) / 처리 완료(서윤 확인) |
| **돈** | 누가 얼마 낼까? | 미정 / 답 기다림 / 합의 · 금액 / 이견 / 비용 없음 |

- 셋은 서로를 막지 않아요. 하자가 "이견"이어도 수리를 시작할 수 있고, 수리가 끝나도 돈은 계속 정할 수 있어요.
- **완전히 끝남** = 수리 "처리 완료" + 돈 "합의" 또는 "비용 없음". 그 전에는 홈의 "고쳤지만 돈이 남은 건"에 떠요.
- 하자가 "맞아요"가 아닌데 수리를 시작하면, 수리 줄 옆에 작게 "보충 요청 중에 시작했어요"처럼 **강행 표시**가 붙어요(막지 않음).

## 2. 응답: 버튼 두 개

상대에게 확인을 요청하는 모든 곳(하자, 지불 금액, 점검 항목, 송금 받음, 고친 내용, 상황 변화)에서 [반드시] 같은 모양이에요. 프론트 부품 하나, API는 기록마다 `respond` 하나(`ACK` / `NEED_MORE` / `DISPUTE`).

**답할 쪽(정호) 화면**
```
┌ 서윤 님이 확인을 요청했어요 · 41시간 남음 ─────────────────┐
│ 욕실 › 세면대 · 수전에서 물이 새요                          │
│ [사진 2장]                                                   │
│        [맞아요]          [아니에요 · 더 필요해요]           │
└──────────────────────────────────────────────────────────────┘
```

**[아니에요 · 더 필요해요]를 누르면**
```
┌ 어떤 건가요? ───────────────────────────────────────────────┐
│ ○ 더 필요한 게 있어요 (사진, 근거, 원인 확인)                │
│ ○ 사실과 달라요                                              │
│ 사유: ______________________________                         │
│                                           [보내기]           │
└──────────────────────────────────────────────────────────────┘
```

| 누르면 | 서버가 하는 일 | 화면 결과 |
|---|---|---|
| [맞아요] | 그 기록에 확인(도장), 기다림 닫힘. 하자라면 하자 줄만 바뀌고 수리 줄은 그대로 | "정호 님 확인 ✓ · 11/15" |
| 더 필요한 게 있어요 | 보류(도장), 기다림 닫힘 | "보충 요청됨 · 사유" |
| 사실과 달라요 | 이견(도장), 기다림 닫힘 | "이견 · 사유" |

- **[맞아요]는 되돌리는 버튼이 없어요.** [반드시] 확인 뒤에 할 말은 진행 상황, 원인 설명, [상황이 바뀌었어요]로 남겨요(5장).
- 보류나 이견은 **정산 완료 전까지 언제든 [맞아요]로 바꿀 수 있어요.** 보류·이견 표시 옆에 작게 (맞아요로 답 바꾸기)를 둬요.
- 하자 [맞아요]는 "이런 하자가 있다"까지예요. **돈을 내겠다는 뜻이 아니에요.** 처음 한 번은 버튼 아래에 "수리비는 따로 정해요" 한 줄을 보여 줘요.

**보류·이견을 받은 쪽(서윤) 화면**
```
┌ 정호 님이 보충을 요청했어요 · "천장 전체 사진이 필요해요" ──┐
│        [보충하고 다시 확인 요청]        (이대로 둘게요)      │
└──────────────────────────────────────────────────────────────┘
```

| 누르면 | 서버가 하는 일 |
|---|---|
| [보충하고 다시 확인 요청] | 사진이나 설명을 **하나 이상 더해야** 보내져요. 새 확인 요청(문자 한 통, 72시간 새로 시작). 한 기록에 **7일에 한 번**만 돼요. 7일 안이면 버튼 자리에 "3일 뒤 다시 요청할 수 있어요" |
| (이대로 둘게요) | 아무것도 바뀌지 않아요. 보류·이견은 표시로 남고 다른 일은 계속할 수 있어요 |

## 3. 고치기: 장면 다섯 개

**규칙 한 줄**: 상대가 확인하기 전에는 그냥 고쳐지고, 확인한 뒤에는 무엇을 고치든(설명, 부위, 금액, 날짜) 상대가 다시 확인해야 바뀌어요. 고치기는 **원래 기록한 사람만** 할 수 있어요.

### 장면 0. 확인 전 고치기
```
욕실 › 세면대 · 수전에서 물이 새요          정호 님 확인 기다림 · 30시간 남음
                                                         (고치기)
→ 고치면 바로 바뀜. 토스트: "고쳤어요"
```
서버: 새 모습을 저장하고 지금 모습을 옮겨요. 정호가 연결돼 있으면 서비스 안 알림 "서윤 님이 고쳤어요".

### 장면 1. 확인 뒤에 고친 직후 (서윤 화면)
```
욕실 › 세면대 · 물이 조금 새요                         정호 님 확인 ✓
┌ 내가 고친 내용 · 정호 님 확인 기다림 ──────────────────────┐
│ "물이 많이 새요"                                  (거두기) │
└────────────────────────────────────────────────────────────┘
```
서버: 앞에 보이는 모습(정호가 확인한 것)은 그대로 두고, 고친 내용을 **칸 하나 + 새 값 + 기준 모습**으로 저장해요. 그 기록에 확인 요청을 하나 만들어요(이미 있으면 거기에 묶어요. 문자는 한 통).

### 장면 2. 정호가 받았을 때
```
욕실 › 세면대 · 물이 조금 새요
┌ 서윤 님이 고쳤어요 ────────────────────────────────────────┐
│ 물이 ~~조금~~ **많이** 새요                                 │
│        [맞아요]          [아니에요 · 더 필요해요]           │
└────────────────────────────────────────────────────────────┘
```
[반드시] 바뀐 글자만 표시해요(지운 글자는 줄 긋기, 새 글자는 굵게). 한눈에 오타인지 내용이 바뀐 건지 알 수 있어야 해요. 여러 칸을 고쳤으면 칸마다 한 줄씩, 맨 위에 [모두 확인]을 둬요.

### 장면 3. 정호가 [맞아요]
```
욕실 › 세면대 · 물이 많이 새요              고쳐짐 · 정호 님 확인 ✓   [고친 이력 ▸]
```
서버: 정호가 **본 그 고친 내용**만 확인해요. 그 사이 서윤이 또 고쳤다면 "내용이 바뀌었어요. 다시 보고 확인해 주세요"로 거절해요. 확인되면 **확인된 모습 + 그 칸만** 합쳐 새 모습을 만들어요(다른 칸의 고친 내용은 딸려 가지 않아요).

### 장면 4. 정호가 거절
```
욕실 › 세면대 · 물이 조금 새요                         정호 님 확인 ✓
┌ 정호 님이 고친 내용에 동의하지 않았어요 ───────────────────┐
│ "물이 많이 새요" · 사유: 지난주에 봤을 땐 조금이었어요     │
│     [사진 더해서 다시 요청]          (이대로 둘게요)       │
└────────────────────────────────────────────────────────────┘
```
- [사진 더해서 다시 요청]: 같은 고친 내용에 근거를 더해 다시 보내요(근거 하나 이상 필수, 7일에 한 번).
- (이대로 둘게요): 거절된 고친 내용은 지워지지 않고 [고친 이력]에 접혀요.
- 금액이었다면 정산 화면의 "이견"에 그대로 보여요.

### 장면 5. 고친 이력 (눌러야 보임)
```
고친 이력
 11/20  서윤  "물이 많이 새요"        정호 님 확인 ✓   ← 지금 보이는 것
 11/18  서윤  "물이 많이 새요"        정호 님 거절 · 사유 …
 11/15  서윤  "물이 조금 새요"        정호 님 확인 ✓
 11/15  서윤  "물이 조금 셈니다"      (확인 전에 고침)
```

**화면 규칙 네 줄** [반드시] (수리 건, 지불, 점검 항목, 송금 모두 같은 부품)
1. 앞에는 언제나 **둘이 확인한 내용 하나**만 크게.
2. 답을 기다리는 고친 내용은 그 아래 **상자 하나**, 버튼은 최대 두 개.
3. 반영되면 "고쳐짐 · ○○ 님 확인" 한 줄만 남고 상자는 사라져요.
4. 거절, 거둠, 지난 모습은 [고친 이력 ▸] 안에 접혀요.

**사진은 고치지 않아요.** 사진은 추가만 돼요(5장).

## 4. 덧붙이기, 새 기록, 고치기: 무엇이 다른가

헷갈리기 쉬워서 먼저 구분해요. **규칙 한 줄: 설명은 자유롭게, 사실은 확인받고, 계산은 확인된 것만.**

| 종류 | 무엇 | 상대 확인 | 계산·합의에 | 문자 |
|---|---|---|---|---|
| **덧붙이기** | 설명을 더함: 사진 추가, 진행 상황, 원인 설명, 잘못 올린 사진 표시 | 필요 없음 | 들어가지 않음 | 없음(서비스 안 알림) |
| **새 기록** | 확인받아야 할 새 사실: 새 수리 건, 새 지불, 정산 항목, 송금 | 자기 확인을 따로 받음 | 확인된 뒤에만 | 확인 요청 한 통 |
| **고치기** | 이미 있는 기록을 바꿈 | 확인 뒤면 필요 | 확인된 모습만 | 확인 뒤면 한 통 |

**헷갈릴 때 묻는 질문**: "그때 적은 게 **틀렸나**(고치기), **설명을 더하고** 싶나(덧붙이기), **새 사실**이 생겼나(새 기록)?"

## 5. 덧붙이기 네 가지

덧붙이기는 **원래 기록과 확인을 건드리지 않고 옆에 더하는 것**이라, 도장(상대 확인) 없이 바로 남아요. 같은 맥락의 이야기는 [반드시] **같은 카드 안에** 쌓여요.

### 5-1. 사진 추가

| | 내용 |
|---|---|
| 언제 | 수리 후 사진, 보충 요청에 답하는 사진, 더 잘 나온 사진 |
| 왜 필요한가 | 보충 요청에 답할 수 있어야 하고, 수리 전·후가 한곳에 모여야 근거가 돼요 |
| 고치기와 다른 점 | 원래 사진은 그대로예요. 사진을 "바꾸는" 기능은 없어요 |

```
사진  [수리 전 2장] [수리 후 1장 · 11/22 · 확인 뒤 추가]     [+ 사진 추가]
```
서버: 사진 기록을 하나 더해요. 상대가 확인한 뒤에 더한 사진에는 "확인 뒤 추가" 표시. 상대에게 서비스 안 알림.

### 5-2. 진행 상황 (+ 상황이 바뀌었어요)

| | 내용 |
|---|---|
| 언제 | "윗집과 합의가 안 돼 공사가 미뤄져요", "업체가 수요일에 와요", "곰팡이가 천장 구멍으로 커졌어요" |
| 왜 필요한가 | **서비스의 핵심.** 막힌 사정이 결정권자에게 바로 닿게 해요(기획서 문제 정의) |
| 고치기와 다른 점 | 원래 하자 기록은 그대로예요. 그때는 그때대로 사실이었고, 지금 상황을 더하는 거예요 |

```
진행 상황
 11/20  정호  업체가 수요일에 와요
 11/22  서윤  곰팡이가 번져 천장에 구멍이 났어요 [사진 1]
              정호 님 확인 기다림 · 70시간 남음          ← "상황이 바뀌었어요"를 켠 경우
                                         [+ 진행 상황 남기기]
```
```
┌ 진행 상황 남기기 ──────────────────────────────────────────┐
│ ______________________________   [+ 사진]                   │
│ □ 상황이 바뀌었어요. 정호 님에게 확인을 요청할게요          │
│                                               [남기기]      │
└────────────────────────────────────────────────────────────┘
```
| 누르면 | 서버가 하는 일 |
|---|---|
| [남기기] (체크 없음) | 진행 상황 기록, 서비스 안 알림 |
| [남기기] (체크함) | 진행 상황 기록 + 확인 요청(문자 한 통, 한 건에 7일에 한 번). 정호는 2장의 두 버튼으로 답해요 |

다른 하자라면 여기가 아니라 **새 수리 건**이에요(6-1).

### 5-3. 원인 설명

| | 내용 |
|---|---|
| 언제 | "업체 소견으로는 윗집 배관이에요" |
| 왜 필요한가 | 판정 없이 "누가 무엇을 근거로 말했나"를 남겨요 |
| 다른 점 | 쪽마다 자기 설명 하나. 상대는 동의·이견만(타이머·문자 없음). **수리비 합의는 바꾸지 않아요** |

```
원인 설명
 정호 · 근거: 업체 소견(○○설비) · 소견서 사진 1 · 서윤 님도 동의 ✓
 서윤 · 근거: 내 추측 · "윗집 욕실 공사 뒤부터 샜어요"
```
[반드시] 근거 종류(내 추측 / 직접 봤어요 / 업체·전문가 소견 / 다른 사람에게 들었어요)를 고르게 해요. "원인 확인됨", "책임 있음" 같은 말은 쓰지 않아요.

### 5-4. 잘못 올린 사진 표시

| | 내용 |
|---|---|
| 언제 | 다른 집이나 엉뚱한 사진을 올렸을 때(개인정보는 아님) |
| 왜 필요한가 | 지우지 않으면서 헷갈림을 줄여요 |
| 다른 점 | 사진은 남고 흐리게 맨 뒤로. 올린 사람이 언제든 붙이고 뗄 수 있어요 |

```
사진  [수리 전 2장] [▒ 잘못 올린 사진 · 11/21 ▒]
```
개인정보가 찍혔으면 이게 아니라 (개인정보 사진 지우기)예요. 파일만 지우고 "개인정보 때문에 지운 사진 · 시각" 흔적이 남아요.

```
지우기 확인 창
┌ 이 사진을 지울까요? ──────────────────────┐
│ 파일이 지워지고 되돌릴 수 없어요.           │
│ 지운 사실과 시각은 기록에 남아요.           │
│ 이미 내려받은 사본에는 남아 있을 수 있어요. │
│ [지우기]  [지우고 가린 사본 올리기]  [취소]  │
└───────────────────────────────────────────┘
상대 화면:  [사진] 가린 사본 · 11/30 (원본은 개인정보 때문에 지움 · 정호 님 확인 뒤)
```
[반드시] "가린 사본"까지만 써요. 같은 사진인지 서비스가 판단하지 않아요.

## 6. 새 기록

### 6-1. 새 수리 건: 같은 맥락인가, 다른 하자인가

```
┌ 다른 문제를 발견했나요? ────────────────────────────────────┐
│ ○ 같은 문제가 커졌어요   → 진행 상황 남기기(5-2)            │
│ ○ 다른 하자예요          → 새 수리 건 (이 건과 연결)        │
└──────────────────────────────────────────────────────────────┘
```
- 같은 곳이 **둘 다 확인해 끝난 뒤** 또 고장 나면 → 새 수리 건(이전 건 연결).
- **한쪽만 확인해 끝난** 건이면 → 상대가 (다시 열기)를 할 수 있어요.

### 6-2. 새 지불

```
지불
 서윤 → 업체  82,000   정호 님 확인 ✓
 서윤 → 업체  10,000   정호 님 확인 기다림   ← 확인 중
```
- 확인되기 전의 지불은 돈 줄에 "**확인 중 +10,000 · 확인되면 나누기에 들어가요**"로만 보여요.
- [반드시] 수리비 나누기의 기준 금액은 **확인된 지불의 합**이에요. 한쪽이 지불을 더하거나 고친 것만으로는 합의가 깨지지 않아요.

## 7. 돈: 수리비 나누기

```
돈 · 수리비 나누기 (확인된 금액 82,000원)       확인 중 +10,000
 제안 1  서윤: 집주인 82,000              → 정호 님이 다른 안
 제안 2  정호: 집주인 60,000 / 세입자 22,000  → 서윤 님 동의 ✓   ← 지금 합의
 제안 3  정호: 집주인 50,000 / 세입자 32,000  → 서윤 님 답 기다림  ← 바꾸자는 안
                                                         [바꾸기]
```
| 규칙 | 화면 |
|---|---|
| 합의는 언제나 하나 | "지금 합의"를 [반드시] 한 줄로 크게 |
| 합의 뒤 새 제안 | 같은 목록에 다음 줄. **상대가 동의할 때까지 지금 합의가 그대로** 정산에 쓰여요("바꾸자는 안 있음") |
| 합의가 풀리는 때 | 확인된 금액이 바뀔 때만. 그때 "전체 금액이 바뀌었어요 · 이전 합의(참고)" |
| 3회째부터 | "직접 이야기해 정한 뒤 제안·동의하면 합의로 남아요" 한 줄 |
| 금액 입력 | 사람별 금액만(비율 없음). 합이 확인된 금액과 같아야 보낼 수 있어요 |

답할 쪽 버튼: [동의] / [아니에요 · 다른 안](사유, 다른 안은 선택). 제안한 쪽: 답하기 전 (거두기), 합의 뒤 [바꾸기].

## 8. "확인 없음" 표시 (상대가 확인하지 않았을 때)

[반드시] 같은 뜻은 하나의 표시로, **줄마다** 붙여요. 기다리는 중과 답이 오지 않은 것은 다른 표시예요.

| 상황 | 보는 사람 | 화면 |
|---|---|---|
| 상대가 아직 없음 | 나 | 호실 맨 위에 **한 번만**: "혼자 기록하고 있어요 · [상대 초대하기]"(줄마다 표시하지 않음) |
| 초대했지만 연결 전 | 나 | 돈·정산 화면 맨 위에 **한 번만**: "정호 님이 아직 연결하지 않았어요 · 돈은 혼자 기록돼요 · [초대 다시 보내기]"(같은 번호로는 7일에 한 번). 링크로 알린 기록에 72시간이 지나면 "정호 님 확인 없음 · 아직 연결하지 않았어요" |
| 연결 전에 끝낸 정산 | 둘 다(내려받기 포함) | "혼자 정리한 정산 · 정호 님은 연결하지 않았어요" |
| 상대가 연결함 | 나 | 서비스 안 알림 "정호 님이 연결했어요 · 이제 함께 확인할 수 있어요", 맨 위 줄이 사라지고 당사자 칸에 "정호 님 · 연결됨 · 11/20" |
| 기다리는 중 | 요청한 쪽 | "정호 님 확인 기다림 · 41시간 남음" |
| 기다리는 중 | 답할 쪽 | 홈 확인 카드(12장). 남은 시간은 답하지 않으면 상대가 혼자 진행할 수 있는 요청("먼저 보면 좋아요")에만 |
| 답이 오지 않음 | 요청한 쪽 | "정호 님 확인 없음 · 72시간 동안 답이 오지 않았어요"(문자를 끈 사람이면 "· 문자를 꺼 두어 서비스 안 알림으로만 알렸어요") |
| 답이 오지 않음 | 답하지 않은 쪽 | "아직 답하지 않은 확인 요청이 있어요 · 지금 답할 수 있어요" + 두 버튼 |
| 그 밖의 이유 | 요청한 쪽 | "정호 님 확인 없음 · 공유를 그만뒀어요 / 탈퇴했어요 / 문자를 그만 받기로 했어요 / 문자가 가지 않았어요" |
| 확인함 | 둘 다 | "정호 님 확인 ✓ · 11/20" |

- 이유가 겹치면 **가장 최근 하나**만 보여요(순서: 탈퇴 → 공유 그만둠 → 문자 그만 받음 → 문자가 가지 않음 → 아직 연결하지 않음 → 답이 오지 않음 → 아직 초대 전). 지난 이유는 [경과]에 남아요.
- "혼자 진행 가능"은 표시가 아니라 **버튼과 안내 한 줄**이에요.
  ```
  정호 님 확인 없음 · 72시간 동안 답이 오지 않았어요
  기다리지 않고 끝낼 수 있어요. 정호 님은 나중에 확인할 수 있어요
                                    [혼자 종료]
  ```
- 이 건에서 정호가 이미 확인 없음(또는 다른 이유로 혼자 진행 가능)이고 그 뒤 정호가 이 건에 한 것이 없으면, 종료 요청 없이 바로 [혼자 종료]가 보여요. 정호에게는 문자 없이 서비스 안 알림만 가요.
- 늦게 온 정호는 정산 전까지 언제든 답할 수 있어요. "처리 완료(서윤 확인)"에 정호가 [종료 확인]을 누르면 "처리 완료(둘 다 확인)"이 돼요.

## 9. 점검과 나란히 보기

```
입주 점검 · 기준: 서윤 · 입주일 3/2                  잠김 · 3/9
 욕실 › 벽·타일   타일 금 [사진]       정호 님 확인 ✓
 방 › 벽          벽지 얼룩 [사진]     보충 요청됨 · "가까이 찍어 주세요"
 현관 › 현관문    긁힘 [사진]          이견 · "도색 뒤라 없었어요"
 주방 › 싱크대    (기록 없음)
```
- 적지 않은 부위는 "이상 없음"이 아니라 [반드시] "**기록 없음**"이에요.
- 모든 항목이 확인 / 보충 요청됨 / 이견 / 확인 없음 중 하나가 되면 잠겨요. 잠긴 뒤에는 무엇을 고치든 상대 확인이 필요해요. 입주일도 함께 잠겨요.
- 보충 요청된 항목은 잠긴 뒤에도 [보충하고 다시 확인 요청]이 돼요.

**퇴거 때 나란히 보기**
```
방 › 벽
 입주 3/2  [사진]  벽지 얼룩 · 정호 님 보충 요청
 수리      (없음)
 퇴거 1/5  [사진]  벽지 얼룩 커짐 · 서윤 · 정호 님 확인 기다림
 표시: 입주 기존 하자
```
입주 때의 상태 표시(확인, 보충 요청, 이견)가 [반드시] 그대로 함께 보여요.

### 9-1. 점검에 무엇을 더하나 (용도와 흐름)

점검은 **그날의 상태**를 남기는 기록이에요. 입주 점검은 원래 있던 하자, 퇴거 점검은 나갈 때의 상태예요. 살면서 생긴 하자는 점검이 아니라 수리 건이에요.

```
더하려는 것이 이미 적힌 하자에 대한 것인가?
├─ 예 → ├ 사진·설명을 더한다          → ① 덧붙이기 (사진 더하기)
│       └ 적힌 내용이 틀렸다          → ② 고치기
└─ 아니요 → ├ 점검 때 있었는데 빠뜨렸다 → ③ [+ 빠뜨린 하자 더하기] (새 기록)
            └ 살다가 생기거나 나빠졌다  → ④ [수리 건 만들기]
```

**작성 중** (서윤이 기준 측)
```
서윤 화면                                   정호 화면
┌ 입주 점검 · 작성 중 ──────────────┐        ┌ 입주 점검 · 서윤 님이 작성 중 ─────┐
│ 욕실 타일 금 (사진 2)             │        │ 서윤 님이 작성 중이에요 · 2일째    │
│ 벽지 얼룩 (사진 1)                │        │ (서윤 님 항목은 보내면 보여요)     │
│ ── 정호 님이 더한 항목 ──         │        │ 내가 더한 항목                    │
│ 베란다 방충망 찢어짐               │        │  베란다 방충망 찢어짐              │
│   [맞아요] [아니에요 · 더 필요해요] │        │  서윤 님 확인 기다림               │
│ [+ 빠뜨린 하자 더하기]             │        │ [+ 빠뜨린 하자 더하기]             │
│              [정호 님에게 확인 요청] │        └───────────────────────────────────┘
└──────────────────────────────────┘
```

**잠긴 뒤**
```
┌ 입주 점검 · 잠김 11/20 ──────────────────────────────────────┐
│ 욕실 타일 금          둘 다 확인 ✓   (사진 더하기) (고치기)       │ ← ① ②
│ 벽지 얼룩             정호 님 확인 없음 · 지금 답할 수 있어요      │ ← 늦게 답하기
│ 베란다 방충망 찢어짐   잠긴 뒤 추가 · 11/30 · 서윤 님 확인 기다림  │ ← ③
│                                     [+ 빠뜨린 하자 더하기]     │
│ ⓘ 살면서 생기거나 나빠진 하자는 [수리 건 만들기]로 남겨 주세요   │ ← ④
└──────────────────────────────────────────────────────────────┘
```

**언제 잠기나**: 모든 항목에, 그 항목을 쓰지 않은 사람의 답(또는 72시간 확인 없음)이 붙으면 잠겨요.
```
11/18  서윤이 확인 요청            → 정호가 답할 항목 2개
11/19  정호가 2개에 답함, 방충망을 더함 → 서윤이 답할 항목 1개 (아직 안 잠김)
11/20  서윤이 방충망에 [맞아요]     → 잠김 🔒
       (서윤이 72시간 답하지 않으면 11/22에 "서윤 님 확인 없음"으로 잠김)
```

| 규칙 | 화면 |
|---|---|
| 버튼 이름 | [반드시] "[+ 빠뜨린 하자 더하기]"(그날 있었던 것만), 바로 아래 ④ 안내 한 줄 |
| 늦게 더한 것 | "잠긴 뒤 추가 · 날짜", "거주 종료 뒤 추가 · 날짜". 그날 있었는지는 판정하지 않고 날짜만 |
| 나빠진 하자 | 잠긴 입주 점검에 더하지 않아요. 수리 건이나 퇴거 점검에 남기고, 나란히 보기에서 함께 보여요 |
| 같은 하자를 둘이 적음 | 둘 다 남고, 확인하는 쪽이 이견("이미 적은 항목과 같아요")을 달 수 있어요 |

---

**입주 점검 시작 · 입주일이 비어 있을 때**
```
┌ 입주 점검 시작 ───────────────────────┐
│ 이 집에 들어온 날을 알려 주세요         │
│ [2025-11-20  ]  계약서의 입주일이에요   │
│                         [다음]        │
└───────────────────────────────────────┘
```
입주일보다 늦게 시작하면 "입주 후 등록(날짜) · 입주 당시 상태와 다를 수 있어요"가 붙어요.

## 10. 정산

```
정산 · 보증금 10,000,000 (둘 다 확인 ✓)

 합의됨                          확인 기다림·확인 없음        이견
 + 누수 수리비 65,000            관리비 −70,000(정호 제안)    도배 −150,000 / 0
                                                            (서윤 이견)
 합의된 항목으로 계산한 금액: 10,065,000
 정해지지 않은 금액: −70,000, −150,000
 확인 중: 지불 +10,000 (정호 님 확인 기다림)

 송금
 정호 → 서윤 10,000,000   서윤 님 받았어요 ✓
 정호 → 서윤     65,000   받았는지 확인 중          ← 송금 합계에 안 들어감
 정호 → 서윤     30,000   서윤 님: 금액이 달라요 · 받은 금액 25,000(서윤 기록)  ← 같은 송금, 합계엔 서윤이 확인한 것만

                                       [정산 끝내기 제안]
```
- 계산은 [반드시] **확인된 금액과 지금 합의만** 써요. 확인 중인 것은 "정해지지 않은 금액"이나 "확인 중"으로 따로 보여요.
- 송금 합계는 **받은 쪽이 확인한 송금만** 더해요.
- 받은 쪽(서윤) 화면의 송금 줄: **[받았어요]** · [아니에요 · 더 필요해요](금액이 달라요, 사유). 금액이 다르면 [받았어요(혼자)]로 실제 받은 금액을 적고, 두 기록은 같은 송금으로 묶여 한 번만 세요.
- **정산 끝내기**: 누르면 상대에게 따로 문자가 가요. 기다리는 동안 정산에 무엇이든 더해지거나 바뀌면 "정산 내용이 바뀌어 끝내기 요청이 닫혔어요 · [다시 요청]"(이때는 7일 제한 없음). 상대가 (아직 안 끝났어요 · 사유)로 답하면 혼자 끝낼 수 없고 다시 요청은 7일 뒤예요.
- 정산이 끝나면 모든 기록이 읽기와 내려받기만 돼요. 남은 확인 요청은 "정산 완료로 닫힘"이에요.

**보증금 카드**: 보증금은 계약 때 정해진 사실을 맞추는 것이라 "제안·합의" 대신 "적기·확인"을 써요.
```
정호 화면 (확인 카드 · 정산 전까지 보면 돼요)
┌ 보증금 ──────────────────────────────┐
│ 서윤 님이 적은 보증금                  │
│ 10,000,000                             │
│ 계약서와 같나요?                       │
│ 확인해야 정산 금액이 계산돼요          │
│ [맞아요]    [아니에요 · 다른 금액]     │
└────────────────────────────────────────┘
둘이 같으면: 보증금 10,000,000 · 둘 다 확인 ✓
아직이면:   계산 금액 자리에 "보증금 확인 전" + 참고값
다르면:     "보증금 금액이 서로 달라요 · 서윤 10,000,000 / 정호 9,000,000"
```

**돈 카드 세 가지의 화면 말** (안은 같은 장치)

| | 수리비 나누기 | 정산 항목 | 보증금 |
|---|---|---|---|
| 내는 것 | 서윤 님 제안 | 서윤 님 제안(금액·사유) | 서윤 님이 적은 보증금 |
| 상대 버튼 | [동의] / [아니에요 · 다른 안] | [동의] / [아니에요 · 다른 안] | [맞아요] / [아니에요 · 다른 금액] |
| 둘이 같음 | 합의 ✓ | 합의 ✓ | 둘 다 확인 ✓ |
| 아직 | 확인 기다림 | 확인 기다림 | 보증금 확인 전 |
| 다시 | [바꾸기] | [바꾸기] | [바꾸기] |

[반드시] 화면에 "안건", "역제안", "보증금 미확인", "보증금 합의"를 쓰지 않아요.

### 10-1. 정산 항목 바꾸기 (돈 안건)

**사실은 고치기, 돈은 바꾸기.** 움직임은 같아요: 확인(합의) 전엔 내가 바로 바꾸고, 뒤엔 상대가 받아들여야 바뀌고, 그 전까지 지금 것이 그대로예요.

```
수리 건 카드 (사실 둘 + 돈 하나)          정산 항목 카드 (돈 하나)
┌ 욕실 수전 ─────────────────┐            ┌ 벽지 손상 ────────────────────┐
│ 하자     맞아요 ✓   [고치기] │ ← 사실     │ 보증금에서 빼기 50,000        │
│ 수리     처리 완료 ✓        │ ← 사실     │ 사유: 벽지 손상 (사진 2)      │
│ 수리비   집주인 65,000      │ ← 돈 안건  │ 합의 ✓ 11/28        [바꾸기]  │ ← 돈 안건
│          합의 ✓   [바꾸기]  │            └───────────────────────────────┘
└─────────────────────────────┘
```
정산 항목의 [바꾸기]는 수리 건 돈 줄의 [바꾸기]와 **같은 부품**이에요(사유도 제안 줄에 함께).

**합의 뒤 바꾸기** (상대가 답하기 전이면 그냥 바로 바뀌어요)
```
서윤 화면                                 정호 화면
┌ 벽지 손상 ───────────────────┐          ┌ 벽지 손상 ───────────────────┐
│ 보증금에서 빼기 50,000       │← 그대로  │ 보증금에서 빼기 50,000        │
│ 사유: 벽지 손상              │          │ 합의 ✓ 11/28                  │
│ 합의 ✓ 11/28                 │          │ ┌ 서윤 님이 바꾸자고 해요 ───┐ │
│ ┌ 내가 바꾸자고 한 안 ──────┐ │          │ │ 50,000 → 40,000            │ │
│ │ 50,000 → 40,000           │ │          │ │ 벽지 ~~손상~~ 일부 찢어짐   │ │
│ │ 벽지 ~~손상~~ 일부 찢어짐  │ │          │ │ [동의] [아니에요 · 다른 안]│ │
│ │ 정호 님 확인 기다림 [거두기]│ │          │ └────────────────────────────┘ │
│ └────────────────────────────┘ │          └──────────────────────────────┘
└──────────────────────────────┘
정산 계산: 50,000 (지금 합의)
```

| 정호의 답 | 앞모습 | 정산 계산 |
|---|---|---|
| [동의] | 40,000 · 벽지 일부 찢어짐 · 합의 ✓ 12/1 | 40,000 |
| [아니에요 · 다른 안](사유) | 50,000 그대로, 아래 "바꾸자는 안 · 정호 님 이견"(정호의 다른 안이 있으면 함께) | 50,000 |
| 답 없음 | 50,000 그대로, 아래 "바꾸자는 안 · 정호 님 확인 없음" | 50,000 |

| 규칙 | 화면 |
|---|---|
| 누가 | [바꾸기]는 양쪽 다 눌러요. 상대가 낸 항목에 다른 금액을 내는 것도 같은 버튼이에요 |
| 여러 번 | 기다리는 내 안은 하나라, 답 전에 또 바꾸면 그 안이 바뀌고 문자는 다시 가지 않아요 |
| 다른 항목 | 부위·종류가 다르면(벽지 → 장판) [제외 제안] + 새 항목 |
| 수리 건에서 온 항목 | [바꾸기] 대신 "수리 건에서 온 항목 · [수리 건 보기]". 내용은 수리 건에서 고치고, 금액은 수리 건 합의를 따라와요 |
| 주고받기 | 횟수 제한 없음. 3회째부터 "직접 이야기해 정한 뒤 제안·동의하면 합의로 남아요" |

## 11. 링크로 보는 화면 (가입 전)

```
┌ homestamp ──────────────────────────────────────────────────┐
│ 서울 ○○구 ○○동의 한 호실 · 정*윤 님이 보낸 기록이에요       │
│ 욕실 › 세면대 · 수전에서 물이 새요                           │
│ [사진 2장]                                                   │
│ 처리 상태: 확인 기다림 · 고친 이력 1                         │
│ 이 건에 수리비 기록이 있어요 · 가입하면 볼 수 있어요         │
│ 여기서 보기만 해서는 답한 것으로 남지 않아요                 │
│        [가입하고 응답하기]  (이메일과 휴대폰 인증, 약 2분)    │
│        (이미 회원이에요: 로그인하고 응답하기)                 │
│                                         (문자 그만 받기)     │
└──────────────────────────────────────────────────────────────┘
```
[반드시] 보이지 않는 것: 호실 별칭, 상세 주소, 이름(가린 이름만), 연락처, 돈의 내용(금액·낸 사람·날짜. 있다는 것만 한 줄), 다른 기록. (문자 그만 받기)는 확인 창을 거쳐요("이 번호로 오는 우리 서비스 문자가 모두 멈춰요").

**연결 확인 화면** (가입·로그인 뒤, 인증 번호 = 초대 번호일 때)
```
┌ ○○동 정*윤 님의 302호에 집주인으로 연결할까요? ─────────────┐
│ 보여 줄 사람 · 보여 주는 것 · 목적 · 기간 · 연결하지 않으면    │
│ (내가 이 호실에 남기는 기록을 세입자 정*윤 님도 봐요)          │
│ 연결하면 정*윤 님에게 알림이 가요.                             │
│ 언제든 공유를 그만둘 수 있어요.                                │
│        [동의하고 연결하기]        [연결하지 않기]              │
└────────────────────────────────────────────────────────────────┘
```
- 두 버튼은 [반드시] 같은 크기, 기본 선택 없음. [연결하지 않기]는 초대한 쪽에 알리지 않고, 받은 링크는 계속 볼 수 있어요.
- 연결하면 앞서 남긴 기록이 모두 보이고, 확인할 것은 확인 카드에 모여요(첫 문자 없음).

## 12. 홈과 확인 카드

```
확인할 일 (12)                          ← 확인 카드
 먼저 보면 좋아요 (2)
   답하지 않으면 서윤 님이 혼자 진행할 수 있어요 · 14시간 남음
 정산 전까지 보면 돼요 (10)
                                     [확인 시작]
오래 멈춘 건 (1)
 방 벽지 · 처리 중 · 18일째                         (진행 상황 묻기)
고쳤지만 돈이 남은 건 (1)
 욕실 수전 · 돈 미정
내 호실
 사는 집 · ○○동 302호
```
모바일에서는 [반드시] 확인 카드를 맨 위에 둬요(문자 링크는 휴대폰으로 열려요).

**확인 카드 안** (한 건씩 넘기기 → 마지막 요약 → 보내기)

```
다 고른 뒤 한 번에 보내요                     1/12
┌ 욕실 수전 · 지불 65,000 ───────────────────┐
│ 영수증 사진 · 11/20                          │
│ 확인해야 수리비 나누기에 들어가요             │
│ [맞아요 ✓]   [아니에요 · 더 필요해요]         │
│                              [다음 ▸] [나중에]│
└──────────────────────────────────────────────┘

이렇게 보낼게요
 맞아요 9 · 더 필요해요 2 · 이견 1   [하나씩 다시 보기]
                          [보내기 (12건)] [더 볼래요]
```

| 규칙 | 화면 |
|---|---|
| 모으는 것 | 지금 답할 수 있는 것 모두(기다리는 것 + 미확인이 됐지만 정산 전이라 늦게 답할 수 있는 것) |
| 두 칸 | "먼저 보면 좋아요"(답하지 않으면 상대가 혼자 진행할 수 있는 것, 남은 시간 보임) / "정산 전까지 보면 돼요"(남은 시간 대신 내 답이 무엇을 하는지). [반드시] 서두르게도 늦추게도 하는 말은 쓰지 않아요("급하지 않아요" 같은 말 없음) |
| 고르기 | 카드 안 버튼은 고른 표시(✓)가 남아요. [나중에]는 그 건을 건너뛰어요. 점검이나 여러 칸을 고친 기록은 그 기록 화면을 열어 골라요 |
| 한 번에 맞다고 하기 | [반드시] 여러 기록을 한꺼번에 맞다고 하는 버튼은 두지 않아요. 한 화면에 다 보이는 한 기록 안(점검의 남은 항목, 고친 칸들)에서만 [모두 확인]이 있어요 |
| 보내기 | [보내기]를 눌러야 답이 돼요. 고른 것만 보내기도 돼요. 바뀐 건은 "내용이 바뀌어 보내지 못했어요 · [다시 보기]"로 돌아와요 |
| 떠날 때 | 다른 화면으로 가면 "고른 3건을 보낼까요? [보내기] [버리기]". 탭을 닫았다가 같은 기기로 돌아오면 "아직 보내지 않은 고른 것 3건이 있어요 · [이어서 보내기] [버리기]"(24시간, 로그아웃하면 지움) |
| 요청한 쪽 | "정호 님이 5/12 확인했어요" |

**문자 보낸 뒤 통지 줄** (보낸 쪽, 기록마다 한 줄)

| 상태 | 화면 |
|---|---|
| 모으는 중 | 곧 보낼게요 |
| 밤·한도로 미뤄짐 | 내일 아침에 보낼게요(이유와 정확한 시각은 말하지 않아요. 시범 운영에서는 서버가 9시에 켜져요) |
| 보냄 | 보냈어요 · 받았는지 확인 중 (받으면 그때부터 72시간을 세요) |
| 전달 | 받았어요 · 확인 기다림 41시간 남음 |
| 열람 | 열어 봤어요 |
| 실패 | 문자가 가지 않았어요 [번호 고치기] [이 번호가 맞아요, 다시 보내기] |

지난 단계는 [알림 이력 ▸]에 시각과 함께 있어요(모은 문자면 "다른 확인 2건과 함께 보냈어요"). [반드시] "발송 성공"이라는 말은 쓰지 않아요(받았다는 오해).
