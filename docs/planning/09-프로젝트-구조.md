## 2. 백엔드 패키지

기준 패키지: `com.chilsuitjo.back`. **도메인별**로 나누고, 도메인 안을 네 층으로 나눠요. 비어 있는 층은 만들지 않아요.

```
com.chilsuitjo.back
├── global/          공통: security, scheduler, error, response, config
├── member/  auth/  room/  inspection/          (A)
├── action/  repair/  correction/               (B)
├── proposal/  payment/  settlement/  photo/    (C)
├── notification/  link/                        (D)
└── respond/         확인 카드 보내기 조립      (D)
```

**한 도메인 안**

```
repair/
├── api/            RepairController, 요청·응답 DTO
├── application/    RepairService(입구), 이벤트 리스너
├── domain/         RepairCase, RepairTransitions(apply), 값 객체
└── infra/          RepairCaseRepository, 외부 호출
```

| 주인 | 패키지 | 내용 |
|---|---|---|
| A | `member` `auth` `room` `inspection` | 회원, 로그인·토큰, 호실·당사자·부위·연결, 입주·퇴거 점검 |
| B | `action` `repair` `correction` | 행동 기록·해시 체인, 수리 건, 고치기 |
| C | `proposal` `payment` `settlement` `photo` | 돈 안건 장치, 지불, 정산·송금·보증금, 사진 |
| D | `notification` `link` `respond` | 응답 요청·기다림·통지·아웃박스, 링크, 확인 카드 |
| 공통 | `global` | 보안, 예약 작업 틀, 오류 응답, 설정 |

## 3. 부르는 방향

**화살표는 위에서 아래로만** 가요. 같은 층끼리는 공개 서비스로만 부르고, 서로 부르지 않아요.

```
[맨 위]   respond
[도메인]  member · auth · room · inspection · repair · proposal · payment · settlement · photo · link
[아래층]  action · correction · notification
[바닥]    global
```

| 규칙 | 내용 |
|---|---|
| 도메인을 넘는 참조 | **ID 값만**(UUID). JPA 관계(`@ManyToOne` 등)는 같은 도메인 안에서만. DB 외래 키는 그대로 둬요 |
| 행동 기록 | 모든 도메인이 `ActionWriter`를 불러요. `action`은 어떤 도메인도 import하지 않아요 |
| 기다림·통지 | 도메인이 `notification`에 요청을 만들고, "혼자 진행할 수 있나"를 물어봐요. `notification`은 도메인을 부르지 않아요 |
| 고치기 | `correction`은 `Correctable` 인터페이스만 두고, 각 도메인이 구현해요 |
| 아래에서 위로 알릴 때 | **같은 트랜잭션 안의 동기 도메인 이벤트**. 예: 지불 금액이 확인돼 바뀜 → `PaymentAmountConfirmed` → `settlement`가 후보를 "다시 확인 대기"로 |
| 확인 카드 | `respond`는 도메인의 공개 서비스만 불러요. 어떤 도메인도 `respond`를 부르지 않아요 |
| 잠금 | 모든 행동은 맨 먼저 **호실 기록 행**을 잠가요(해시 체인 번호). 같은 호실의 행동은 한 줄로 서서 이벤트가 끼어도 교착이 없어요 |

**같은 도메인 층끼리 방향 (초안, 1일차 확정)**

| 부르는 쪽 → 불리는 쪽 | 이유 |
|---|---|
| `repair` → `proposal` | 수리비 나누기 안건 |
| `settlement` → `proposal` | 정산 항목·보증금 안건 |
| `settlement` → `repair`, `payment` | 후보 계산(읽기) |
| `repair`, `inspection`, `payment`, `settlement` → `photo` | 사진 붙이기 |
| `room` ← 모두 | 호실·당사자·권한 확인 |
| `link` → `repair`, `inspection` | 링크로 보여 줄 기록 읽기 |

**ArchUnit 검사 (CI)**

```java
@ArchTest static final ArchRule 고리_없음 =
    slices().matching("com.chilsuitjo.back.(*)..").should().beFreeOfCycles();

@ArchTest static final ArchRule action은_도메인을_모른다 =
    noClasses().that().resideInAPackage("..action..")
        .should().dependOnClassesThat().resideInAnyPackage(
            "..member..", "..room..", "..inspection..", "..repair..",
            "..proposal..", "..payment..", "..settlement..", "..photo..", "..link..");

@ArchTest static final ArchRule 누구도_respond를_부르지_않는다 =
    noClasses().that().resideOutsideOfPackage("..respond..")
        .should().dependOnClassesThat().resideInAPackage("..respond..");
```

## 4. 이름 규칙

| 무엇 | 이름 | 예 |
|---|---|---|
| 컨트롤러 | `*Controller` | `RepairController` |
| 입구 서비스(공개 인터페이스, 커버리지 대상) | `*Service` | `RepairService` |
| 상태 전이(`apply`, 커버리지 대상) | `*Transitions` | `RepairTransitions` |
| 저장소 | `*Repository` | `RepairCaseRepository` |
| 도메인 이벤트 | 과거형 | `PaymentAmountConfirmed` |
| 불변식 테스트 | `@Tag("invariant-NN")` | `@Tag("invariant-06")` |
| 테이블 · 칼럼 | snake_case(ERD 그대로) | `repair_case.confirmed_content_id` |
| 코드 이름 | GLOSSARY 단어를 따름 | 고치기 = `correction`, 행동 기록 = `action` |

## 5. 프론트엔드

```
front/src/
├── pages/              화면(라우트 하나에 하나)
├── features/<도메인>/   그 도메인의 부품·훅(repair, payment, settlement …)
├── components/ui/      shadcn 부품
├── components/common/  공통 부품(확인 없음 표시, 고친 내용 상자, 안건 카드, 확인 카드)
├── api/                OpenAPI로 만든 타입과 호출 함수(손으로 쓰지 않음)
└── lib/                유틸
```

| 규칙 | 내용 |
|---|---|
| 같은 뜻은 한 부품 | 확인 없음 표시, 고친 내용 상자, 돈 안건 카드, 응답 두 버튼은 `components/common`에 하나씩(`08-화면-기본-틀.md`) |
| 버튼 | 서버가 준 `availableActions`로만 보이고 숨겨요 |
| API 타입 | CI가 만든 OpenAPI 파일로 생성해요 |
| 저장 | 토큰은 메모리·쿠키만, `localStorage`에는 확인 카드 임시 고른 것(24시간)만 |
