# homestamp 사용자 시나리오

세입자와 집주인이 집 상태·수리·퇴거 정산 기록을 함께 남기는 장면입니다.

---

## 1. 등장인물

| 역할 | 사람(가상) | 상황 |
|---|---|---|
| 세입자 | 정서윤, 27세 회사원 | 원룸 월세 2년 계약 |
| 집주인 | 김정호, 58세 | 원룸 8호실 관리, 다른 동네 거주, 앱 설치를 꺼림 |

## 2. 기본 규칙

| 규칙 | 내용 |
|---|---|
| 형태 | 반응형 웹. 문자 링크를 누르면 설치 없이 열림 |
| 가입 | 휴대폰 인증 한 번. 응답하려면 가입 후 호실에 연결 |
| 기록 | 사실은 혼자 남길 수 있고, 합의는 혼자 만들 수 없음 |
| 확인 | 상대가 [맞아요]를 누르면 "같이 확인함". 그 뒤 고친 내용은 상대가 확인해야 반영 |
| 기다림 | 48시간 뒤 재통지, 24시간 뒤 "확인 없음". 혼자 진행 가능 |
| 돈 | 확인된 금액과 합의된 항목만 계산 |
| 문자 | 답해야 하는 일만, 같은 때 가는 것은 한 통으로 |

## 3. 시나리오 1. 거주 중 하자 → 수리 → 종료

| # | 누가 | 하는 일 | 상태 |
|---|---|---|---|
| 1 | 세입자 | 가입 → 호실 기록 만들기 | - |
| 2 | 세입자 | 욕실 천장 물 자국 사진 2장 등록 → 집주인에게 알리기(공유 동의) | 하자: 확인 기다림 |
| 3 | 서버 | 집주인에게 문자(링크) | - |
| 4 | 집주인 | 링크로 사진·설명 확인 → 가입 → 호실에 연결 | - |
| 5 | 집주인 | 하자 [맞아요] | 하자: 맞아요 |
| 6 | 집주인 | 수리 시작 | 수리: 처리 중 |
| 7 | 세입자 | 수리비 65,000원 지불 기록 + "집주인 부담" 제안 | 돈: 합의 대기 |
| 8 | 집주인 | 금액 확인, 부담 동의 | 돈: 합의 |
| 9 | 집주인 | 종료 요청 | 수리: 종료 확인 대기 |
| 10 | 세입자 | 수리 후 사진 + 종료 확인 | 수리: 처리 완료 → 완전히 끝남 |

**갈림길**

| 상황 | 처리 |
|---|---|
| 집주인이 답하지 않음 | 72시간 뒤 "확인 없음". 세입자 혼자 수리·종료 가능, 돈은 혼자 기록(합의 안 됨) |
| 하자를 인정하지 않음 | [아니에요 · 더 필요해요] → 보류 또는 이견(사유). 수리는 누구든 시작 가능, 세입자는 근거를 더해 다시 요청 |
| 부담에 동의하지 않음 | 이견 + 다른 안(예: 32,500원씩). 합의될 때까지 이어짐 |
| 확인 뒤 내용을 고침 | 확인된 내용은 그대로 두고 고친 내용이 아래에 붙음 → 상대가 확인하면 반영 |
| 아직 안 고쳐짐 | 종료 요청에 "아직 안 됐어요"(사유) → 처리 중 |
| 수리가 멈춤 | 14일 넘으면 "오래 멈춘 건" → 진행 상황 남기기·묻기 |

## 4. 시나리오 2. 집주인이 먼저 시작 → 입주 점검

| # | 누가 | 하는 일 | 상태 |
|---|---|---|---|
| 1 | 집주인 | 가입 → 호실 기록 만들기(세입자 번호) | - |
| 2 | 집주인 | 입주 점검: 기존 하자와 사진 → 세입자 초대 | 점검: 확인 기다림 |
| 3 | 세입자 | 링크 → 가입 → 연결 | - |
| 4 | 세입자 | 항목마다 [맞아요] / [아니에요], 빠뜨린 하자 더하기 | - |
| 5 | 집주인 | 세입자가 더한 항목 확인 | - |
| 6 | 서버 | 모든 항목에 답(또는 확인 없음)이 붙으면 잠금 | 점검: 잠김 |

- 적지 않은 부위는 "이상 없음"이 아니라 "기록 없음"으로 표시합니다.
- 잠긴 뒤 빠뜨린 하자는 "잠긴 뒤 추가(날짜)"로, 살면서 생긴 하자는 수리 건으로 남깁니다.

## 5. 시나리오 3. 세입자 혼자 기록

| # | 누가 | 하는 일 | 상태 |
|---|---|---|---|
| 1 | 세입자 | 집주인 번호 없이 호실 기록 만들기 | 혼자 기록 중 |
| 2 | 세입자 | 입주 점검·하자·사진·지불을 혼자 기록 | 확인 없음 |
| 3 | 세입자 | 나중에 집주인 초대 | - |
| 4 | 집주인 | 연결 → 그동안의 기록이 확인 카드에 모임 → 하나씩 확인 | 같이 확인함 |

- 연결하지 않은 상대에게는 돈 확인 요청이 가지 않고, 링크 화면에는 금액이 보이지 않습니다.
- 끝까지 연결하지 않으면 정산은 "혼자 정리한 정산"으로 남고, 내려받기로 바깥에서 공유합니다.

## 6. 시나리오 4. 퇴거 → 정산 → 보증금 반환

| # | 누가 | 하는 일 | 결과 |
|---|---|---|---|
| 1 | 세입자 | 퇴거 점검 시작(같은 부위 사진) | 정산 열림 |
| 2 | 둘 다 | 부위마다 입주·수리·퇴거 사진 나란히 보기 | - |
| 3 | 세입자 | 보증금 10,000,000원 적기 → 집주인 [맞아요] | 보증금: 둘 다 확인 |
| 4 | 둘 다 | 수리 건 후보 넣기: 누수 +65,000(집주인 부담, 세입자가 냄) | 합의 |
| 5 | 집주인 | 직접 입력: 관리비 −70,000, 도배 −150,000 | 확인 기다림 |
| 6 | 세입자 | 관리비 동의, 도배는 이견("입주 기존 하자") + 다른 안 0원 | 관리비: 합의, 도배: 이견 |
| 7 | 서버 | 합의된 항목으로 계산: 10,000,000 − 70,000 + 65,000 = **9,995,000원** | 정해지지 않은 금액 −150,000 |
| 8 | 집주인 | 9,845,000원 반환 기록 → 세입자 수령 확인 | - |
| 9 | 세입자 | 퇴거 점검 마침 | 거주 종료 |
| 10 | 둘 다 | 도배 75,000원으로 합의 → 75,000원 반환·수령 확인 | - |
| 11 | 둘 다 | 정산 끝내기 요청 → 확인 | 정산 완료(1년 뒤 삭제) |

- 정산 항목을 넣거나 빼는 것도 상대 확인이 필요합니다.
- 반환을 기록하지 않아도 세입자는 혼자 "받았어요"를 남길 수 있습니다.
- 끝내기를 기다리는 동안 정산이 바뀌면 끝내기 요청은 다시 보내야 합니다.
- 상대가 끝내기에 반대해도 거주 종료 90일 뒤 자동 마감됩니다.

## 7. 문자 예시

```
① 첫 문자(초대)
[homestamp] 정*윤님(302호)이 집 수리 기록을 보여 드리려고
이 번호를 입력했어요.
요청: 욕실 천장 물 자국 확인
보기: https://homestamp.cloud/l#a8Kx…
그만 받기: https://homestamp.cloud/l#a8Kx…/stop

② 재통지
[homestamp] 302호 수리 기록 확인 요청이 아직 남아 있어요.
https://homestamp.cloud/l#a8Kx…

③ 연결된 회원(여러 건을 한 통으로)
[homestamp] 302호: 확인할 일 3건이 있어요.
https://homestamp.cloud/r/…
```

금액과 홍보 문구는 문자에 넣지 않습니다.
