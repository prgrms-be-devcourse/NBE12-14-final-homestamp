# 유출 대응 런북

> 개인정보가 새거나 샜을 가능성을 알았을 때 따르는 한 쪽짜리 절차예요. 법률 자문이 아니고,
> **서버가 꺼져 있어도 할 수 있게** 썼어요. 통지 문자는 솔라피 콘솔에서 직접 보내고, 신고는 개인정보 포털에서 해요. 주말에 서버가 꺼져 있어도 72시간 기한은 흘러가요.

## 0. 담당

| 역할 | 사람 | 하는 일 |
|---|---|---|
| 책임 | 개인정보 보호책임자(팀 대표, 권리 요청 메일 담당과 같은 사람) | 판단, 통지, 신고 |
| 기술 | 배포 담당 | 막기, 범위 확인 |
| 기록 | 나머지 1명 | 사고 문서, 시각, 사본 보관 |

## 1. 알게 된 시각을 적는다

사고 문서(팀 비공개 문서) 첫 줄에 **"알게 된 시각, 누가, 어떻게"**를 적어요. 72시간은 이때부터 세요. 72시간 안에 통지하지 못하면 이 시각을 입증해야 해요.

## 2. 먼저 막는다

| 사고 | 막는 방법 |
|---|---|
| A. 초대 문자가 잘못된·재활용된 번호로 감 | 그 링크 닫기(번호 고쳐 다시 초대하면 자동 무효) → 링크 열람 기록 확인 |
| B. 링크 토큰이 샘 | 그 링크 닫기 → 열람 시각·횟수로 범위 확인 |
| C. 사진 주소가 샘 | 주소는 짧게 살아 저절로 닫힘. 필요하면 그 사진을 "링크에서 숨김". S3 접근 로그(30일)로 열렸는지 확인 |
| D. DB 비밀번호·AWS 자격 증명·JWT 서명 키 유출 | Parameter Store 값 교체 → 앱 재배포 → 리프레시 토큰 전부 폐기 → 보안 그룹·IAM 확인 → CloudTrail·RDS 로그로 접근 범위 확인 |
| E. 번호 HMAC 키만 유출 | 키는 바꾸지 않음. CloudTrail로 DB·S3에 함께 접근했는지 확인. 함께 샜으면 D로 |

## 3. 판단한다

| 결과 | 다음 |
|---|---|
| 모르는 사람이 내용을 볼 수 있는 상태가 됐음(링크가 열림, 불법 접근 확인) | 4. 통지 |
| 불법 접근 흔적은 있는데 누구 것인지 모름 | **유출 가능성 통지**("확인되면 다시 알려 드려요" 포함) |
| 아니었음이 확인됨 | 내부 기록만. 가능성 통지를 했으면 "유출되지 않았어요"를 바로 알림 |

| 사고 | 유출인가 | 누구에게 알리나 | 신고 |
|---|---|---|---|
| A | 링크가 열렸으면 유출. 안 열렸으면 문자 본문(가린 이름·동)만 감 | 기록을 남긴 측 | 대상 아닐 가능성(우리가 보낸 것, 1천 명 미만, 민감 정보 없음) |
| B | 모르는 사람이 열었으면 유출 | 기록을 남긴 측 | 원칙적으로 아님. 토큰을 훔쳐 쓴 정황이면 검토 |
| C | 만료 전에 누가 열었으면 유출 | 사진을 올린 측 | 아님 |
| D | 불법 접근이 확인되면 유출, 흔적만 있으면 가능성 | 해당 회원(가능성이면 해당될 수 있는 모두, 비회원 상대 번호 포함) | **외부 불법 접근이면 1명이라도** |
| E | 유출 아님 | 없음(내부 기록) | 없음 |
| (참고) 문자 업체 쪽 유출 | 업체 통보를 받아 판단 | 해당 회원 | 업체 신고 여부 확인 |
| (참고) Slack 웹훅 주소 유출 | 개인정보 없음(숫자만 보냄) | 없음 | 없음, 웹훅만 재발급 |

## 4. 통지한다 (72시간 안)

- **방법**: 문자 + 서비스 안 알림. 연락처가 없으면 공지 페이지에 30일 게시.
- **항목** (모르는 항목은 아는 것만 먼저 보내고 확인되면 다시 보내요)
  1. 어떤 정보가
  2. 언제, 어떻게
  3. 지금 할 수 있는 일
  4. 우리가 한 조치와 피해 구제 절차
  5. 문의처
  6. 손해배상·분쟁조정 등 권리와 방법(개인정보 분쟁조정위원회 안내)
  7. 더 확인되면 다시 알림
- 6번은 법이 요구하는 고지라 원칙 3(법적 판단 문구 금지)의 예외예요. 통지 밖의 화면에는 쓰지 않아요.

**통지 문구 초안 (A·B 링크가 열린 경우)**

```
[homestamp] 개인정보 유출 안내
○월 ○일 ○시에 ○○동 호실 기록 링크가 의도하지 않은 사람에게 열린 것을 확인했어요.
열린 내용: 표시 이름(가림), 사진 ○장, 설명, 처리 상태와 시각
한 조치: ○월 ○일 ○시에 그 링크를 닫았어요. 링크는 더 열리지 않아요.
할 수 있는 일: 기록 화면에서 공유 상태를 확인하고, 필요하면 상대를 다시 초대해 주세요.
문의: (팀 메일)
개인정보 침해로 피해를 입었다면 손해배상을 청구하거나 개인정보 분쟁조정위원회(www.kopico.go.kr)에 조정을 신청할 수 있어요.
더 확인되는 내용이 있으면 다시 알려 드릴게요.
```

**통지 문구 초안 (D 가능성)**

```
[homestamp] 개인정보 유출 가능성 안내
○월 ○일 ○시에 서비스 운영 키가 외부에 노출된 것을 확인했어요.
지금까지 확인한 것: (확인한 범위)
아직 확인 중인 것: 회원 정보에 접근했는지 여부
한 조치: 키를 바꾸고 모든 기기에서 로그아웃시켰어요. 다시 로그인해 주세요.
문의: (팀 메일)
개인정보 침해로 피해를 입었다면 손해배상을 청구하거나 개인정보 분쟁조정위원회(www.kopico.go.kr)에 조정을 신청할 수 있어요.
확인되면 72시간 안에 다시 알려 드릴게요.
```

## 5. 신고 여부를 정한다 (72시간 안)

- 외부 불법 접근이면 **1명이라도**, 1천 명 이상이거나 민감·고유식별 정보면 개인정보 포털(privacy.go.kr)에 신고해요.
- 회수·삭제로 위험이 현저히 낮아졌으면 신고하지 않을 수 있어요. 그때는 **판단 이유를 사고 문서에** 적어요.

## 6. 사후

- 원인, 조치, 재발 방지를 이슈 한 건으로 남기고, 규칙이 바뀌면 `docs/decisions.md`에 한 줄 더해요.
- 통지·신고 사본을 팀 비공개 문서에 보관해요.
- 문자 업체와 관련된 사고면 업체 통보 내용을 붙여요.
- 이 런북은 1주차 교육(30분)에서 함께 읽어요.
