# 개요: 왜, 누구를 위해, 무엇을

> homestamp가 푸는 문제, 사용자, 다른 점, MVP 범위(하는 것·안 하는 것)를 한 장에 모은 문서예요. 규칙과 화면은 다음 문서들에 있어요(`../README.md` 읽는 순서).

## 한눈에

- **관리 단위는 호실이다.** 한 거주 기간(입주~퇴거)의 입주 점검, 수리 건, 수리비, 퇴거 정산, 권한이 모두 호실 기록 하나에 모인다.
- **세입자는 혼자 써도 가치가 있다.** 집주인이 가입하지 않아도 기록, 통지, 열람 기록, "확인 없음"이 남는다.
- **응답하려면 회원가입이 필요하다.** 가입 때 휴대폰 인증을 한 번 하고, 임대인·임차인 모두 호실을 만들고 상대를 초대할 수 있다. 링크로 들어온 사람은 공유받은 기록만 읽는다.
- **수리와 돈은 따로 끝난다.** 수리는 돈 합의와 상관없이 끝낼 수 있고, "고쳤지만 돈이 남은 건"을 따로 모아 본다.
- **사실은 혼자 남길 수 있고, 합의는 혼자 만들 수 없다.** 서비스는 판정하지 않는다.

**한 줄 소개**: 입주부터 퇴거까지 집 수리를 함께 남기는 기록

> 원룸·다가구에는 아파트 관리소나 기숙사처럼 수리를 접수하고 기록하는 창구가 없다. 그래서 하자가 생기면 연락이 부동산, 관리인, 집주인 사이에서 끊기고, 퇴거 때는 "원래 있던 하자인지, 누가 내기로 했는지"를 근거 없이 다툰다.
> homestamp에서 세입자가 하자를 사진과 함께 올리고 집주인에게 알리면, 집주인 휴대폰으로 문자 링크가 가고 언제 열어 보고 언제 확인했는지가 고칠 수 없는 기록으로 남는다. 입주 점검, 거주 중 수리, 퇴거 정산이 호실 기록 하나에 이어지므로, 퇴거 날에는 쌓인 기록이 그대로 정산의 근거가 된다.

## 1. 문제

**지인이 겪은 장면: 다가구 원룸 월세, 천장 누수**

1. 천장 곰팡이를 중개한 **부동산**과 건물 **관리소**에 알렸고, 둘 다 "조금 지켜보자"고 했다.
2. 곰팡이가 번져 천장에 구멍이 났다. 집주인도 점검했고, 윗집 쪽에서 물이 새는 것까지 확인했다.
3. **2개월 동안 멈춤.** 부동산은 "윗집과 합의가 안 돼 6개월 정도 버텨 보라"고 했는데, **집주인은 그 사정도, 그 말도 몰랐다.** 관리소는 담당자가 바뀌어 "처음 듣는 얘기다, 기록 남긴 게 있느냐"고 했다.
4. 세입자가 집주인에게 직접 연락하자 **1개월 안에** 일단락됐다.
5. 그동안 세입자는 사진, 카톡 캡처, 통화 녹음을 혼자 모았지만 흩어진 기록을 하나로 관리하기 어려웠다.

| 끊긴 곳 | 무슨 일이 있었나 |
|---|---|
| 중간 전달자 | 막힌 사정이 **결정권자(집주인)에게 닿지 않았다** |
| 담당자 교체 | 경과가 **사람에게 붙어 있다가** 사람이 바뀌자 사라졌다 |
| 확인 여부 | 누가 언제 무엇을 알렸고 무엇이 확인됐는지를 **아무도 같은 기록으로 보지 못했다** |
| 증빙 | 사진, 카톡, 녹음이 **각자의 휴대폰에 흩어졌다** |

비슷한 사건에서 세입자가 낸 통화 기록이 중개업소와의 통화뿐이자, 법원은 그것만으로는 임대인에게 통지했다고 인정하기 부족하다고 보고 배상 범위를 줄였다(서울중앙지방법원 2014. 6. 20. 선고 2014나13609 판결, 확정).[^판결] 누구에게 언제 알렸는지가 남지 않으면 세입자가 불리해진다.

**문제 한 문장**

> 세입자와 집주인은 집 상태와 수리의 기록을 함께 보지 못해서, 수리는 늦어지고 퇴거 때 보증금을 근거 없이 다툰다.

| 왜 중요한가 | 내용 |
|---|---|
| 분쟁 규모 | 주택임대차분쟁조정위원회(한국부동산원·LH)의 2025년 접수 983건 중 **유지·수선 의무가 238건(24.2%)으로 2위**, 1위는 보증금·목적물 반환(321건, 32.7%)[^조정] |
| 증가 속도 | 유지·수선 접수가 2023년 63건 → 2024년 111건 → 2025년 238건, **2년 새 약 3.8배**[^조정] |
| 상대가 나오지 않으면 | 2022년 1월~2026년 7월 임차인 신청 각하 4,382건 중 **79.9%는 임대인의 조정 참여 거부**[^각하]. 조정 전에 쌓아 둔 기록이 그만큼 중요하다 |
| 대상 규모 | 1인 가구 824만 가구(일반가구의 36.6%)[^가구], 청년가구의 82.6%가 임차[^주거] |

손실은 수리 기술이 부족해서가 아니라 **누가 언제 무엇을 알았는지가 같은 기록으로 남지 않아서** 생겼다. 빠짐없이 보내는 통지, 고칠 수 없는 경과, 호실마다 정하는 권한은 백엔드가 직접 풀 수 있는 문제다.

## 2. 지금은 어떻게 하나, 무엇이 다른가

| 대안 | 하는 것 | 그런데도 남는 문제 |
|---|---|---|
| 카톡·문자·전화·단톡방 | 누구나 이미 씀 | 확인 여부가 대화에 묻히고, 분쟁 때 **경과표를 손으로 다시 만든다** |
| 사진·캡처·녹음 각자 보관 | 세입자 혼자 증빙 | 휴대폰마다 흩어지고, 상대가 언제 확인했는지는 남지 않는다 |
| 네스트실 | 입주 상태 기록, 열람 링크 | 입주 시점 중심. 거주 중 수리 흐름은 찾지 못했다 |
| 자리톡, 동거동락 등 | 월세 고지·수납, 임대 장부 | 돈 중심, 집주인용 |
| 아파트아이, LH바로픽스 | 민원 접수·처리 | 관리 조직이 있어야 쓴다. 원룸·다가구에는 없다 |
| Fixflo(영국) | 한 수리 건을 여럿이 함께 봄 | 중개사가 관리하는 영국 구조의 B2B |

**한 줄 차별점**: 관리 조직이 없는 원룸·다가구에, 기숙사 수준의 수리 창구와 고칠 수 없는 기록을 준다.

1. **결정권자에게 바로 보낸다.** "알리기"를 누르면 중간 전달자를 거치지 않고 집주인 휴대폰으로 문자 링크가 간다. 보냈는지·열었는지·확인했는지가 경과에 남는다(실제로 읽었다는 보장은 아니다). 중개사·관리인을 MVP 당사자로 넣지 않은 이유도 끊기는 곳이 중간 전달자이기 때문이다.
2. **고칠 수 없는 한 흐름으로 남긴다.** 수정·삭제 기능이 없고 덧붙이기만 한다. 잘못은 [고치기]로 바로잡고(같이 확인한 뒤면 상대가 확인해야 바뀜), 이견은 원래 기록과 나란히 남긴다.
3. **모든 것이 호실 하나에 모인다.** 권한도 호실마다 정한다. 같은 사람이 A호실에서는 세입자, B호실에서는 집주인일 수 있다.
4. **사진이 정리되어 있다.** 사진은 항상 **부위 × 단계(입주 / 수리 전·후 / 퇴거)**에 묶이고, 퇴거 때 같은 부위의 사진이 나란히 보인다.
5. **판정하지 않는다.** 책임, 과실, 금액을 서버가 정하지 않는다. 실제 돈은 오가지 않고 돈이 오간 사실만 기록한다.

## 3. 사용자

| | 세입자 정서윤(핵심) | 집주인 김정호(보조) |
|---|---|---|
| 상황 | 27세 개발자, 서울 다가구 원룸(보증금 1,000만 원, 월세 60만 원) 2년 계약의 1년 차. 집주인은 다른 동네, 중개는 근처 부동산 | 58세, 다가구 1동(원룸 8호실)을 물려받아 관리. 문자·카톡은 잘 쓰지만 새 앱 설치는 꺼림 |
| 겪는 문제 | 욕실 천장 물 자국을 부동산에 알렸지만 일주일째 소식이 없고, 집주인이 아는지 확인할 방법이 없다. 입주 때 있던 벽지 얼룩을 확인한 적이 없어 보증금에서 빠질까 걱정 | 하자 연락이 여기저기서 따로 와서 어느 호실이 언제 고쳐졌는지 모아 볼 곳이 없다. 퇴거 때 보여 줄 입주 사진이 없어 원상복구 이야기가 길어진 적이 있다 |
| 바뀌는 것 | 부위를 고르고 사진을 올려 알리면 "링크 열람"과 "확인"이 시각과 함께 남는다. 퇴거 때는 쌓인 기록으로 정산하고 보증금을 받으면 "받았어요"로 남긴다 | 링크를 가입 없이 열어 보고, 응답하려고 가입하면 호실이 한곳에 모인다. 입주 점검을 확인해 두면 퇴거 때 같은 부위 사진이 나란히 보인다 |

집주인이 얻는 것: 원상복구 근거(입주 점검 잠금, 나란히 보기), 수리 연락이 한곳에, 중간 전달자 없이 사정을 바로 앎, 정산 장부 불필요, "제때 고쳤다"는 기록. 판정하지 않고 양쪽의 사실만 남기기 때문에 세입자만 편드는 도구가 아니다. 집주인 페르소나는 실제 인터뷰 없이 세운 가설이다.

**어떻게 쓰이게 하나**: 세입자부터 모으고, 집주인은 세입자가 보내는 링크로 들어오게 한다(설치 없는 웹).

- 집주인이 가입하지 않아도 성공으로 본다. 세입자가 혼자 정리용으로 쓰고 "확인 없음"이 남는 것도 가치다.
- 4주 안에는 실제 사용자 시범 운영을 하지 않고, 실제 집주인도 초대하지 않는다(동의하지 않은 사람에게 문자를 보내지 않기 위해). **문자는 팀원에게만 간다.** 가치는 수강생 질문지(응답 30명 목표)와 시연(시나리오 2개)으로 확인한다.
- 시범 운영 기간에는 서버가 평일 9~18시에만 켜진다. 코드는 24시간 서비스로 만들어 서버가 켜질 때 밀린 일을 따라잡는다.

## 4. MVP 범위

| # | 기능 | 한 줄 설명 | 우선순위 |
|---|---|---|---|
| 1 | 호실 기록과 참여 | 기록과 권한을 호실마다 모은다. 임차인·임대인 모두 호실을 만들고 상대를 초대하며, 링크로 들어온 사람은 공유받은 기록만 읽고 응답은 가입·연결 뒤에 한다 | Must |
| 2 | 수리 건의 경과 (포인트 기능) | 하자를 부위·사진과 함께 올리고 알리면 문자 통지가 가고, 확인·고치기·종료(수리 상태)와 수리비·부담 합의(돈 상태)가 따로 고칠 수 없는 경과로 남는다 | Must |
| 3 | 입주·퇴거와 정산 기록 | 입주 때 기존 하자를 양쪽이 확인해 잠그고, 퇴거 때 같은 부위 사진을 나란히 보며 정산 세 칸(합의됨 / 확인 기다림·확인 없음 / 이견)과 보증금 반환·수령을 남긴다 | Must |

**MVP가 3개인 이유**: 흐름의 **입구(참여), 가운데(수리), 양 끝(입주·퇴거)**이다. 하나라도 빠지면 "입주부터 퇴거까지 한 흐름"이 끊긴다. 세 기능은 같은 기록 구조(**호실 → 부위 → 수리 건 → 행동 기록**)를 쓰고, 깊게 파는 기술은 **덧붙이기만 하는 기록**과 **통지 전달 보장(트랜잭셔널 아웃박스)** 두 개다. 기능별 요구사항과 우선순위는 `06-요구사항-명세.md`.

**확장(MVP와 P1 뒤)**: 실사용자 시범 운영, 기준 사진 재사용·여러 호실 대시보드·관리인 위임, 같은 집 기록 합치기, 카카오 로그인, 계약서 사진에서 정보 뽑기, 웹 푸시(서비스 워커), 링크 본인 인증과 기기 기억, 송금 앱으로 이동하는 버튼, 동거인·당사자 교체, 이전 거주 기간 이어받기, 월세·관리비 장부·계약 만료 알림, 탈퇴 철회 유예, 댓글 채팅.

**하지 않음(Won't)**

- 실제 결제·송금, 거래내역 연동(돈이 오간 "사실"만 기록)
- 책임·과실 판정, 법률 판단(사실만 남기고 판단은 사람이)
- 기록 수정·삭제 기능(바로잡기는 [고치기], 예외는 개인정보가 찍힌 사진 파일만)
- 주민등록번호 받기, 외부 OCR·외부 CDN·외부 분석 도구
- 영상 업로드(사진만), 증빙의 진위·금액 자동 판독
- 계약 전 서류 확인, 모바일 앱, 카카오 알림톡(반응형 웹 + 문자)
