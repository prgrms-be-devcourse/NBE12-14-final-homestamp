# homestamp 문서

세입자와 집주인이 집 상태·수리·퇴거 정산 기록을 함께 남기는 반응형 웹, homestamp(homestamp.cloud)의 기획·설계 문서예요. **여기가 원본**이고, 노션 등은 사본이에요. 이 폴더만 읽으면 무엇을, 왜 그렇게 만드는지 알 수 있게 썼어요.

## 읽는 순서

| 순서 | 문서 | 무엇을 |
|---|---|---|
| 1 | `rules/00-개요.md` | 왜, 누구를 위해, 범위(하는 것·안 하는 것) |
| 2 | `rules/01-이야기로-보는-흐름.md` | 이야기 세 개로 보는 전체 흐름(예시) |
| 3 | `rules/02-사용자-시나리오.md` | 시나리오별 장면과 갈림길(예시, 시연 대본) |
| 4 | `rules/06-요구사항-명세.md` | **기준 문서.** 기능마다 수용 기준·API·오류 코드·설정값, 그리고 주제마다 더 깊게 읽을 곳 |
| 5 | `rules/03-상태와-규칙.md` | 상태 전이, 권한, 보이는 범위, 불변식, 개인정보 정책 |
| 6 | `rules/05-ERD-초안.md` | 테이블, 칸, 행동 종류 |
| 7 | `rules/08-화면-기본-틀.md` | 화면 그림과 문자 문구 |
| 옆 | `rules/GLOSSARY.md` | 낱말 뜻. 화면·코드·문서는 이 말을 써요 |
| 개발 | `rules/04-인프라-아키텍처.md` · `rules/09-프로젝트-구조.md` · `rules/07-WBS.md` | 인프라·배포 / 패키지·이름 / 일정 |

- `decisions.md`: 결정 기록(유일). **왜 그렇게 정했는지**는 여기서 찾아요.
- `runbooks/`: 운영 절차(유출 대응).
- `setup.md`: AI 하네스(Claude·Codex), IDE 코드 서식, 로컬 실행 처음 설정.
- `failure-memory.md`: AI가 반복한 실수 기록. 기록은 사람이 승인한 것만 더해요.
- 그림은 문서 안의 Mermaid 코드예요. GitHub에서 바로 그려져요.

## 개발할 때는

**기준은 `rules/06-요구사항-명세.md`예요.** 06에서 기능을 보고 틀을 잡은 뒤, 기능 표의 "규칙" 칸을 따라 03(상태와 규칙), 추적표를 따라 05(테이블)로 가면 더 깊게 나와요.
주제마다 어디로 가는지, 문서끼리 다를 때와 문서를 바꾸는 법은 06 0장 "주제별로 더 깊게"에 있어요.

넣지 않는 것: 기록 수정·삭제 기능, 판정·법적 판단 문구, 주민등록번호 처리, 외부 CDN·외부 OCR, 비밀값 커밋(`decisions.md` 원칙).
