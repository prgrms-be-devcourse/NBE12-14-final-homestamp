# HomeStamp 프론트엔드

호실 기록, 수리, 입주·퇴거 점검과 정산 화면입니다. 지금은 서버 없이 **목업**으로 모든 화면이 동작하고, 실제 API 연동은 기능마다 이어서 붙입니다.

## 실행

Node.js 22를 권장합니다. 자세한 환경은 [팀 설정 문서 7장](../docs/setup.md#7-로컬-실행-모두-필수)을 참고하세요.

```sh
cd front
npm ci
npm run dev
```

Vite가 터미널에 표시한 주소를 여세요. 기본 주소에는 확인용 101호가 열리고, 주소에 `?sample`을 붙이면 연남하우스 302호와 망원빌라 201호의 예시 기록으로 시작합니다.

| 쪽     | 이메일            | 개발용 비밀번호 |
| ------ | ----------------- | --------------- |
| 세입자 | `test@gmail.com`  | `aaaa1111`      |
| 집주인 | `test1@gmail.com` | `aaaa1111`      |

두 계정은 목업 전용입니다. 새로고침하거나 새 탭을 열면 목업 기록이 초기화됩니다. 같은 탭에서 로그아웃하고 다른 계정으로 로그인하면 앞서 남긴 기록에 상대 쪽으로 응답할 수 있습니다.

## 목업 모드와 HTTP 모드

`VITE_API_MODE`로 고르고, 고르는 곳은 `src/api/create-api.ts`(기록)와 `src/api/auth.ts`(계정·인증) 두 곳뿐입니다.

|                  | 목업(`mock`)                                               | HTTP(`http`)                                                                                                                                                                                                                                                                                                                                             |
| ---------------- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 기본으로 쓰는 때 | `npm run dev`, `npm test`                                  | `npm run build`(배포 빌드)                                                                                                                                                                                                                                                                                                                               |
| 기록             | 브라우저 메모리(`src/api/mock/`). 새로고침하면 처음 상태   | 서버(`VITE_API_BASE_URL`, 기본은 같은 출처 `/api`)                                                                                                                                                                                                                                                                                                       |
| 계정·인증        | 위 개발 계정 두 개. 문자는 보내지 않고 인증번호는 `123456` | 서버. 로컬 서버는 문자를 보내지 않으니 인증번호는 [`docs/postman/README.md`](../docs/postman/README.md) "인증번호 알아내기"로 찾습니다                                                                                                                                                                                                                   |
| 화면 표시        | 맨 위에 "예시 모드" 띠                                     | 없음                                                                                                                                                                                                                                                                                                                                                     |
| 지금 상태        | 모든 화면이 동작                                           | **로그인·재발급·로그아웃·내 정보·이름·문자 설정·비밀번호 변경·재설정·약관 다시 확인, 가입·휴대폰 인증(인증 문자 보내기·인증번호 확인), 법정동 찾기·단계 선택, 호실 만들기·목록·상세, 부위 목록·더하기·숨기기·다시 보이기·켜고 끔, 받은 초대·연결·거절만 연결했습니다.** 나머지 요청은 서버로 가지 않고 "아직 서버에 연결되지 않은 기능이에요"로 멈춥니다 |

HTTP 모드는 `src/api/connected.ts`의 **연결을 마친 API 목록**에 있는 요청만 서버로 보냅니다. 요청·응답 모양이 서버와 아직 다른 요청이 가서 400·404가 나거나 잘못 기록되지 않게 하려는 것입니다. 배포 빌드에는 목업 코드와 개발 계정이 들어가지 않습니다(Vite가 모드 값으로 빼 줍니다).

액세스 토큰(15분)이 만료돼 요청이 401(`LOGIN_REQUIRED`)이면 `src/api/http-client.ts`가 재발급한 뒤 같은 `Idempotency-Key`로 한 번만 다시 보냅니다. 계정 요청과 기록 요청이 `src/api/auth.ts`의 `session` 하나를 같이 써서, 동시에 401이 와도 재발급은 한 번만 갑니다(04 4-1 "동시 재발급"). 재발급도 401(`LOGIN_REQUIRED`·`REFRESH_REUSED`)이거나 다시 보낸 요청도 `LOGIN_REQUIRED`면 세션을 끝내 로그인 화면으로 보내고, 연결 오류·서버 오류는 로그아웃으로 보지 않습니다(#191). 로그인·로그아웃마다 세션 번호가 바뀌어, 그 전에 보낸 요청의 재시도나 늦게 온 재발급 결과는 버립니다(이전 계정의 요청이 새 계정 토큰으로 가지 않게).

바뀐 약관을 확인하기 전이라 상태를 바꾸는 요청이 403(`TERMS_UPDATE_REQUIRED`)이면 `session`이 알리고 화면이 내 정보를 다시 받아 약관 확인 창(`src/features/member/terms-reconfirm-dialog.tsx`)을 엽니다(CONS-4a). 거절된 요청은 그 화면이 오류로 안내하고, 확인한 뒤에도 다시 보내지 않습니다(사람이 다시 누름). 로그인·새로고침 복원 직후 `GET /api/me`의 `pendingAcknowledgements`가 비어 있지 않을 때도 확인 창을 먼저 띄우고, [나중에]로 닫으면 보기만 할 수 있습니다. 내 계정 창에서 [다시 확인]으로 다시 엽니다. 확인 전에도 문자 끄기와 비밀번호 바꾸기는 됩니다(이름 바꾸기·문자 켜기는 403으로 확인 창이 열림). 문구는 가입 화면의 약관 요약·처리 안내를 그대로 쓰고(`src/features/member/terms-text.ts`), 옛 판·바뀐 점은 제공된 문구가 없어 보여 주지 않습니다. 목업에는 다시 확인할 문구가 없습니다.

## 시연 경로

1. `?sample`로 시작해 세입자 계정으로 로그인합니다. **호실 기록 → 연남하우스 302호 → 하자 · 수리 기록**에서 상세 화면과 사진을 봅니다. 새 하자 기록을 남긴 뒤 같은 탭에서 집주인 계정으로 로그인해 응답 화면을 확인합니다.
2. **호실 기록 → 망원빌라 201호 → 퇴거 · 정산**에서 입주·퇴거 비교와 정산을 봅니다. 송금은 상대가 확인한 금액과 확인을 기다리는 금액을 따로 표시합니다.
3. 가입 전 화면은 새 탭에서 개발 서버 주소에 `?sample&share=leak`를 붙여 확인합니다.

송금 보류·금액 이견과 `받았어요(혼자)`, 공유 그만두기·다시 공유, 확인 카드, 진행 상황 남기기는 아직 화면이 없습니다.

## 폴더와 역할

기준은 [`docs/rules/09-프로젝트-구조.md`](../docs/rules/09-프로젝트-구조.md) 5장입니다.

| 폴더                 | 하는 일                                                                                                                                                                                                                                                                                                  |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pages/`             | 화면 하나에 파일 하나(공유 링크 화면 `share-page` 포함). 기록을 읽고 버튼은 `availableActions`로만 그립니다                                                                                                                                                                                              |
| `features/<도메인>/` | 그 도메인의 부품·훅·입력 창. 폴더 이름은 `.github/CODEOWNERS`의 도메인과 같습니다(`auth`, `member`, `room`, `inspection`, `repair`, `proposal`, `payment`, `settlement`, `photo`). 입력 창은 `…-form.tsx`로 자기 칸 상태·확인·보내기를 함께 가집니다. 다른 도메인 폴더는 사진 보기(`photo`)만 불러옵니다 |
| `components/common/` | 여러 도메인이 같이 쓰는 부품(응답 버튼, 보충 요청, 고친 내용 상자, 돈 안건 카드, 확인 없음 표시, 긴 글 펼치기, 입력 창 틀 `form-dialog`, 사진·구역 칸, 안내·빈 화면, 옆 메뉴·위쪽 막대·제목 줄)                                                                                                          |
| `components/ui/`     | shadcn 부품                                                                                                                                                                                                                                                                                              |
| `api/`               | 화면이 부르는 계약(`types.ts`, `repair-cases.ts`, `records.ts`, `available-actions.ts`), HTTP 구현(`http-*.ts`), 연결을 마친 API 목록(`connected.ts`)                                                                                                                                                    |
| `api/mock/`          | 서버 대신 동작하는 목업. **`api/` 밖에서는 불러오지 않습니다**                                                                                                                                                                                                                                           |

`App.tsx`는 화면 틀·주소 이동과 어느 입력 창을 열지만 정하고, 기록을 보내는 함수(`commit`·`act`·`send`, 모양은 `lib/record-commands.ts`)를 창에 넘깁니다. 목업 전체 기록에서 내가 볼 수 있는 것을 거르는 계산도 아직 `App.tsx`에 있는데, HTTP로 연결하면 서버 응답으로 바뀌는 부분입니다.

## 백엔드를 연결할 때 고칠 곳

화면 코드는 바꾸지 않고 `api/` 안만 고치는 것이 목표입니다. 기능 하나를 연결할 때마다 `api/connected.ts`에 그 API를 한 줄 더합니다.

1. **요청·응답 모양**: dev 백엔드와 다른 곳이 있습니다. 하자 사진 `uploadTickets`·보충 `{description, uploadTickets}`, 응답 결과 `AnswerResult`. 가입·휴대폰 인증은 `auth.ts`의 `createHttpAuth`가 서버 모양(`displayName`·`verificationTicket`·문구 판 `v1`, 인증 응답 `{id}`·`{ticket, expiresAt}`)으로 바꿔 보냅니다(#208). 호실은 `http-rooms.ts`가 서버 모양(`side` `TENANT`·`LANDLORD`, 목록 `{items, nextCursor}`, 상세)과 화면 모델을 바꾸고, 서버 값(`counterpartStatus`·`myStatus`·`joinedAway`·`availableActions` 등)은 `room.server`에 그대로 둡니다. 공유를 그만둔 상대·탈퇴한 상대는 `connection`이 `연결됨`이어도 `connectionText`로 따로 보입니다. 만들 때 상대 번호는 `counterpartPhone`으로 보내고 서버가 상대 자리를 `NUMBER_ONLY`로 저장만 합니다(초대·문자 없음, #163 후속). 서버는 저장한 번호를 가린 모양(`counterpartMaskedPhone`, 만든 측에만)으로만 돌려주고, 초대 창은 번호만 자리면 번호를 비워 보내 저장한 번호로 초대합니다(다른 번호를 넣으면 서버가 덮어씀, `invite-form.tsx`). 받은 초대는 `http-invitations.ts`가 자리 ID(`partyId`)를 `id`로 둔 호실 자리표로 바꾸고, 연결 응답의 `roomRecordId`로 연결한 호실에 들어갑니다. 연결·거절 본문에는 받은 초대 줄의 초대 회차 `inviteId`를 함께 보내고, 번호를 고쳐 다시 초대해 회차가 바뀌었으면 서버가 `INVALID_STATE`로 막아 받은 초대를 다시 받습니다(#437). 공유 동의 문구 판은 `v1`(`SHARE_CONSENT_VERSION`)로 보냅니다. 부위는 `http-parts.ts`가 호실마다 목록을 받아 두고, 수리 건·점검 기록은 부위 ID(`roomPartId`)로 가리킵니다. 화면 글자("구역 · 부위")는 ID로 목록에서 찾아 만들어 이름이 같은 방·욕실 "천장"을 가립니다. 고르는 칸(`components/common/part-field.tsx`)은 숨긴 부위·꺼 둔 설비·가전을 빼고, "기타 (직접 입력)"은 고른 구역에 부위를 더한 뒤 그 부위를 고릅니다(06 S-10, #356). 부위 숨기기·다시 보이기·켜고 끔은 호실 홈의 부위 관리 카드(`features/room/room-parts-card.tsx`)에서 하고, 버튼은 호실 상세 `availableActions`의 `parts`가 있을 때만 보입니다. 바꾸면 같은 호실의 부위 칸이 모두 목록을 다시 받습니다(`use-room-parts.ts`, #456).
2. **응답 변환**: `http-api.ts`, `http-records.ts`, `http-repair-cases.ts`의 `toNotices`·`toView` 등은 지금 `as`로만 맞춥니다. 서버 응답(OpenAPI)이 정해지면 화면 모델(`data/demo.ts`)로 바꾸는 함수로 채웁니다.
3. **읽기**: `http-records.ts`의 `load`는 호실(목록을 끝까지 받은 뒤 호실마다 상세)·받은 초대(`GET /api/invitations`)·알림만 받습니다. 알림은 아직 연결 전이라 빈 목록으로 둡니다. 입주 점검은 경과(`GET /api/rooms/{id}/timeline`)의 점검 시작 줄에서 ID를 찾아 상세를 받고, `http-inspection-view.ts`가 화면 모델로 바꿉니다(서버 값은 `room.moveIn.server`·항목 `server`). 점검 주소는 `inspectionIdIn(room, kind)`로 서버 점검 ID를 써서 만듭니다(목업은 자리표 `inspectionIdOf`, #357). 사진을 함께 보내는 행동은 `postWithPhotos`로 만들고, `http-records.ts`가 보내기 전에 업로드 표로 올려 본문 `uploadTickets`에 넣습니다(연결 전 주소면 올리지 않음). 정산·퇴거 점검을 채워야 합니다.
4. **버튼**: `http-available-actions.ts`는 기록마다 붙은 `availableActions`를 읽습니다. 2번 변환에서 서버 값을 붙여 주면 됩니다. 입주 점검이 없을 때는 호실 상세의 `inspections`(입주 점검 시작만)가 시작 버튼입니다(정산 상세는 아직 빈 목록).
5. **06에 주소가 없는 행동**: `notInSpec(...)`으로 표시했습니다(`grep -rn notInSpec src`). 팀이 주소를 정하면 `post(endpoints...)`로 바꿉니다.
6. **사진**: 지금은 브라우저에서 data URL로 읽습니다(`lib/photos.ts`). 서버가 생기면 업로드 표(PHO-1) 번호를 보냅니다.
